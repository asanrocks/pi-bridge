# Changelog

## [Unreleased]

### Breaking Changes

- The daemon no longer auto-starts a session; clients land in a "No instance selected" initial state. Instances are created on demand via the `[+]` button.
- `liveSessionId` removed from `GetDaemonInfoReply`. Per-instance session ids are now in `InstanceInfo.sessionId` from the `listInstances` verb.
- `Connection` constructor no longer takes a `Manager` parameter. Connections start unattached; call `attach(manager, instanceId)` to attach.
- `DaemonVerbs` interface expanded with routing verbs (`switchInstance`, `newInstance`, `killInstance`) and `listInstances`.
- Store fields `activeSessionId` and `liveSessionId` replaced by `attachedInstanceId` and `instances`.
- Reconnect no longer auto-pushes a `replace` — the client drives re-attachment from its stored `attachedInstanceId`.
- `Status.model` is now a `ModelRef` struct `{ provider: string; modelId: string }` instead of a bare id string. The provider was previously dropped at `deriveModel`/`reconcile`/manager boundaries, so same-id models from different providers collided. New `ModelRef` type exported; `ReconcileOptions.model` and the `currentProviderModel` picker prop (renamed `currentModelRef`) take the struct.
- `ViewModelInput.sessions` removed — `computeViewModel` never read it (the web client's last producer, the Project-home history slice, is gone). Callers pass `{ document, models }`.

### Added

- Git change cards and v2 stamp payloads (ADR 10 v2): stamps now record the HEAD commit subject and are observed at two more boundaries — after every agent tool finishes (`tool_end`, the awaited handler places the stamp between the committing tool's call and its result) and after a user `!` command's entry persists (`user_bash_end`, host-triggered from the `entry_appended` event; new `Manager.executeBash` verb is the producer). Mid-run stamps (`tool_end`/`turn_end` with an open run) fold into the run instead of splitting it: the action group's collapsed summary leads with a `git:` hash segment (`git: ae02c151 · edit: foo.ts · run 1 tool · read 3 files`), the family-dot legend gains a leading git swatch (diff/merge green, `--kind-git`), and expansion renders the change as its own slim green card inside the group, after the step it follows. Prompt-anchored stamps render no card at all — the user turn's header chip (`⎇ dev-bridge @ 00a00e98`, commit subject as its tooltip) is their UI; other boundary stamps (user-bash, run anchors with no open run) keep standalone cards. v1 stamps in existing sessions remain readable; the transition key is still `{ commit, branch }` — subject and anchor never affect dedup. Subject lookup is best-effort (`git log -1 --format=%s`): failure yields `commitSubject: null` and never invalidates identity. Both cards reuse the tool-card skeleton (`.actionStep` band in the git family hue, fold row with the subject as summary and branch + short hash docked right, expanded `.detailsCard` with a full identity line above the content region) — and expanding a card with a resolvable commit fetches `git show --stat` on demand via the new `gitShow` daemon verb (hex-validated commit, 5s timeout, 128 KB cap; `gitShowRpc`/`useGitShow` on the client, cached per expansion; unreachable commits render a graceful "not available" state).

- File links render in-app: markdown links with file-path hrefs (relative like `./docs/x.md`, absolute, `~/…`, or `file:///…`) open an in-app file viewer instead of navigating to a 404 on the daemon origin. New `readFile` daemon verb reads the file fresh from disk (256 KB cap with a truncation notice; relative paths resolve against the attached instance's cwd server-side; `~` expands) — the read never enters LLM context. Click handling: a custom Streamdown link renderer classifies hrefs (`features/viewer/links.ts`); URL links keep an external-link confirm step, restyled to the app's portal tokens instead of Streamdown's default modal. `render/Markdown` gained a `components` passthrough; the app wiring lives in `features/viewer/AppMarkdown` (used by all five markdown hosts).

- Syntax-highlighted shell command identity lines: expanded bash/powershell cards render the whole command in the identity line through the shared Shiki singleton (grammar per tool name, github-light token colors) instead of the plain secondary-tone text. New `BashIdentity` component; until the grammar loads (first shell card only) it renders the raw string — identical to the previous display — and every non-shell identity line is unchanged.

- Git identity stamps (ADR 10): bridge-created instances record the repository's HEAD commit and branch as `custom` session entries (`pi-bridge.git-stamp`) at prompt and turn-end boundaries — only on identity transitions, with the baseline derived from the active session path (fork-safe, no process-local state). The viewmodel folds stamps into `UserTurn.gitIdentity` and the web user-turn header shows a muted chip (`⎇ main @ a1b2c3d`; detached HEAD shows the hash only). Stamp data never enters LLM context; `createManager({ gitStamps: false })` is the test seam. Shared payload/validation lives in the browser-safe core export (`GIT_STAMP_CUSTOM_TYPE`, `parseGitStamp*`, `GitIdentity`).

- Back to the instance list: a sidebar button detaches the tab from its instance (new connection-local `detachInstance` verb — patches stop flowing, the instance keeps running headless) and returns to the Launcher. The choice survives reconnects: a `launcherPinned` store flag suppresses the sole-instance auto-attach until the next explicit attach.

- Write and edit card parity: write cards show the tool's confirmation line ("Successfully wrote N bytes to …") under the content; edit cards normalize malformed model output before diffing (new `normalizeEditArgs` — TUI `prepareArguments` parity: `edits` as a JSON string, a single edit object, or the legacy top-level `oldText`/`newText` pair all render the diff the tool executed; the edit copy payload uses the normalized `newText` union). The `powershell` tool joins the bash card family — same summary/identity, status-chip parsing, output body, timeout annotation, and band tail preview (bash hue), via a shared shell-tool set in the card layer and a `powershell` case in `kindForTool`.

- User-initiated shell runs (`! command`) render in the web transcript. New `bash_execution` wire entry (projected from pi `bashExecution` messages — command, output, exitCode, cancelled, truncated, fullOutputPath, excludeFromContext; wire-eager), a `UserBashTurn` in the viewmodel (its own turn between user/assistant turns, chronologically where it ran), and a `UserBashView` card reusing the tool-card skeleton: `$ command` band in the bash hue, status light + `exit N`/`cancelled`/`truncated`/`not in context` chips, sanitized output in the capped details panel with copy/wrap controls and the copyable full-output path. `!!` runs (excluded from LLM context) render muted. pi's `AgentSession.recordBashResult` now emits `entry_appended` so live viewers see user bash without waiting for the next turn to settle (the TUI ignores non-custom `entry_appended`; no behavior change there).

- grep/find/ls result bodies (TUI parity): the three search tools replace their args-only key-value grids with real result renderers — match/listing output lines (wrap-toggleable, shared `.cardOutput` block with bash) plus a truncation warning strip driven by the tool_result `details` object (`N matches limit`, `N result limit`, `N entry limit`, `some lines truncated`, `30KB limit` — lazy-pulled like content). Their identity lines carry the full call (`/pattern/ in path (glob) limit N`, `pattern in path limit N`, `ls path limit N`), and their collapsed bands preview the head of the results (first 5 lines + `… N more lines`).

- Read compact classifications (TUI parity): the collapsed band summarizes `SKILL.md` reads as `[skill] <folder>` and agent-resource files (`AGENTS.md`, `AGENTS.override.md`, `CLAUDE.md`, …) as `read resource <path>`, with the line range preserved. The TUI's pi-docs classification (`README.md`/`docs/*` under pi's own package root) needs daemon-side installation-path knowledge and is deferred.

- Output sanitization (TUI `getTextOutput` parity): tool-result text is stripped of ANSI escapes (commands that colorize), binary control characters (kept: tab, newline), Unicode format characters, and stray carriage returns before it reaches card content, previews, or copy payloads (new `sanitize.ts`; applied centrally via `useResultText`/`ActionDetails`). Code surfaces get deterministic `tab-size: 4` — raw tabs are kept for copy fidelity instead of the TUI's space replacement.

- Collapsed-band result previews (TUI parity): with the details folded, bash steps show a live tail of the command output (last 5 lines, `… N earlier lines` hint) — it streams while the command runs, since a pull subscribes the connection to the result's content patches — and any failed call shows the first line of its error text in the band. Result pulls stay bounded: only bash and failed calls register result wants, and steps render solely inside expanded groups.

- Status chips and truncation strips: the pi tools append exit/timeout/abort status lines and truncation footers to the *text* of tool results; the card layer now parses them back out (new pure `resultText.ts`) so they render as meta instead of leaking into content. Bash failures show an `exit N` / `timed out after Ns` / `aborted` chip beside the status light; truncated bash output shows a warning strip with a copyable full-output temp-file path; truncated reads show the tool's continuation notice (`Use offset=N to continue.`) as a warning strip instead of trailing text inside the code. Copy payloads strip the parsed meta (bash copy = bare output, read copy = file content).

- Hover-revealed card controls, docked right in the card top bar: copy (primary payload per tool — file content for read, written content for write, the `newText` union for edit, command output for bash/fallback), a line-wrap toggle (off gives code and output horizontal scroll), a markdown toggle (`.md` file content renders as prose or source), and the "show all" cap toggle — the old always-visible step-header cap chip, swallowed into the bar. Clipped details now show a persistent bottom fade that signals hidden content (and hides once the scroll window reaches the tail); on hover-incapable pointers (touch) the controls are always visible. Store-wide `cardWrap`/`cardMarkdown` toggles (defaults: wrap on, markdown on).

- Tool cards render a shared card skeleton above the content panel (new `CardSkeleton.tsx`): a status line (status light + live-witnessed duration + `timeout Ns` annotation docked beside the light — the timeout no longer rides the bash command line, where it read as a command argument), a full-form identity line (new pure viewmodel export `makeActionIdentity`: cwd-relative full path with the read line range, or the whole multi-line bash command — the band summary stays abbreviated, expanding restores the full truth), and a skeleton-owned error strip.

- New push kind: `instance_exit` — sent to Connections attached to a killed instance.

- `Manager` exposes `cwd` accessor (delegates to `runtime.cwd`).

- `cwdAllowlist` in `GetDaemonInfoReply` — exposes allowlist to client for the cwd picker menu.
- `cwdAllowlist` Zustand store field — tracked by the client and used by the sidebar's Instances `[+]` button.
- History pane: a git-log-style branch graph of user messages, as a docked right pane (desktop) / right drawer (mobile) toggled from the TopBar's right edge. New pure viewmodel functions `computeHistoryTree`, `computeActiveUserPath`, `computeLaneLayout` (Pass 1 history tree + Pass 2 lane layout); a `HistoryPane` component renders SVG vertical lineages + cubic-Bezier fork curves over positioned DOM rows. Lane assignment is lane-based, not depth-based: the primary child inherits the parent's lane (linear follow-ups stay vertical), secondary forks reuse a freed lane strictly above the parent's (or a fresh rightmost lane) so curves always sweep right. The pane opens scrolled to the deepest on-path node. Clicking a node navigates to the newest leaf of its subtree and anchors the conversation scroll to the message; during streaming, on-path clicks are look-only (anchor-scroll, no branch) and off-path clicks are disabled until the reply settles (branching mid-stream rewrites `agent.state.messages` and races the in-flight turn).
- Draft collapse: aborted-dead-end sibling user messages (assistant turn aborted, no user-message follow-up down that branch) fold into the following keeper as `discardedDrafts` via a new `collapseDrafts` viewmodel pass. Pass 2 sees keepers only, so typo-fans no longer fan into separate lanes. `HistoryPane` renders a "+N drafts" badge on keepers with an expandable popover of the collapsed drafts.
- Turn-header timing: user turns show `thought for Xs` (gap from the most recent assistant completion across all branches — not the leaf-path predecessor — to the send, so re-editing history message A into A0 anchors on the old branch's leaf assistant); assistant turns show `worked for Xs · tools Ys` once sealed (total span minus Σ assistant-generation windows; parallel tools count once via per-batch max, not a per-tool sum). New `UserTurn.thoughtForMs` and `AssistantTurn.{turnStartedAt,totalMs,toolMs}` fields; a live `working for Xs · N running` fragment shows on the in-flight turn (client-clock tick + running-tool count, swapped to the server value at seal). Omitted when no assistant has completed before the send (the first turn).
- Pending-steer visibility: `applyEvent` now handles `queue_update`, surfacing the session's steer queue as a wire-eager `Status.pendingSteer: string[]` field (FIFO; drained as subsequent user turns). `followUp` is not surfaced (steer-only MVP). See `docs/04-prd-web-ui.md` §Steering.
- New wire verb `discardSteer` (typed `DiscardSteerRequest`, `BridgeClient.discardSteer()`, `Manager.discardSteer()`) clears all pending steer/follow-up messages from the session queue. Effect arrives via push (the `queue_update`→`/status/pendingSteer` patch) ahead of the RPC reply, per §7.11.
- Web Composer renders one draft chip per queued steer above the textarea (italic, muted) with a `×` that calls `discardSteer`. The composer stays expanded while steers are pending so drafts remain visible after Stop (no hidden pending state). `useRpc.discardSteer` wired through `App`.
- Send/Stop wiring: Send is always available — during streaming it queues a steer (Manager.prompt already uses `streamingBehavior: "steer"`), when idle it starts a normal turn. The red Stop button now appears **alongside** Send during streaming/compaction instead of replacing it. Send is disabled only when disconnected, empty, or compacting. Removes the `isBusy` guard that previously blocked all sends mid-stream (making steering unreachable from the UI).
- `Manager.abort()` now clears the session steer queue before aborting. Without this, the post-abort auto-continue (`agent-session._handlePostAgentRun` → `hasQueuedMessages` → `agent.continue` → `steeringQueue.drain`) would deliver queued steers as a new turn — i.e. Stop would send the steers instead of cancelling.
- Stop salvages pending steers: the Composer's stop handler backfills the queued steer texts (newline-joined, prepended to any in-progress input) into the textarea before calling abort, so drafts aren't lost when the server-side queue is cleared. The user reviews/edits and re-sends as a normal prompt.
- Keyboard navigation for the web UI. A new `infra/keybindings.ts` owns all document-level shortcuts via one scope-guarded `useAppKeybindings` hook (bails on text inputs for bare reading keys; lets modifier combos through; suppresses app keys while a modal owns the scope). Turn navigation: `j`/`k` focus the prev/next turn (system dividers skipped), `g`/`G` jump to first/last; the focused turn gets a faint accent ring and is scrolled into view (`scroll-margin` clears the fixed TopBar/Composer). `Enter` toggles the focused turn's first action group, `e` edit-to-forks the focused user turn, `y` copies it, `h`/`l` walk the sibling branch pager (scoped to focused user turns with siblings). `Alt+↑`/`Alt+↓` cycle attached instances; `Alt+N` creates a new instance (direct when the cwd allowlist has one entry, surfaces the sidebar's cwd picker otherwise). The existing `/` (expand composer) and `Ctrl+P`/`Ctrl+Shift+P` (cycle model) shortcuts migrated into the hook; Composer's `expanded` state moved to the store so the hook can drive `/`.

- Durable composer drafts: the textarea content is now a store-owned `ComposerDraft` (idle/compose/edit discriminated union) rather than Composer-local `useState`, so it survives composer collapse, blur, and page refresh. A `useDraftGuard` hook persists compose drafts to `localStorage` keyed by session id (globally unique — an instance's current session changes on `switchSession`/`newSession`, so instance id is not a stable conversation key) and restores on attach; a `beforeunload` listener warns when any non-empty draft would be lost.
- Tab completion now works in edit mode (the previous `!isEditing` guard is dropped — editing a message often involves editing paths).
- Pane-toggle keybindings: `Ctrl/Cmd+B` toggles the left Sidebar, `Ctrl/Cmd+H` toggles the right HistoryPane. Both are global (work while the composer textarea is focused); bare `h`/`l` branch-sibling navigation is unaffected (no-modifier keys).

### Changed

- Sidebar interaction model: the dual open/closed panel is now tri-mode — hidden, docked rail, and fullscreen. The rail's resize handle is a mode switch with live snap previews at both bounds (preview == release predicate, so the on-screen state never lies): dragging below the min width snaps the sidebar fully shut mid-drag — the width clamps at the min until the threshold, then pane and gutter disappear at once, and dragging back wider within the same gesture snaps it back open — while dragging past the max width snaps the fullscreen overlay in mid-drag (dragging back under the max snaps it out; the drag keeps its pointer capture under the overlay). The release decides: below the min hides the sidebar, above the max fullscreens it (pure overlay above the top bar, close button docked at the hamburger's corner position so the same screen corner toggles it, plus Esc; `--sidebar-w` stays 0 so the conversation keeps full width), and both overshoot releases restore the pre-drag width first, so backing out of either state is an undo. Mobile drops the half-width drawer for the same full-screen overlay and has only hidden/fullscreen. The top-bar hamburger shows only in mobile mode or desktop-with-sidebar-hidden; on desktop it toggles the rail and hover-peeks a temporary drawer (full-height overlay above the top bar, same content, hides when the pointer leaves, with a short grace timer bridging the hamburger→drawer gap; its own hamburger button at the top-bar hamburger's position pins the rail open — one corner toggle: hamburger opens, peek's hamburger pins, fullscreen's ✕ closes), and an always-invisible 12px drag strip at the far left edge (full viewport height, col-resize cursor only) reveals a hidden rail pointer-absolute — the implied width is the pointer's x position and the rail appears only once that exceeds the min (before then the drag previews closed; a release below the min keeps it hidden with the pre-drag stored width restored). Rail visibility persists in localStorage independent of the rail width; `ResizeHandle` gained opt-in `onOvershootChange` (live snap preview) + `onOvershoot` (release decision), HistoryPane behavior unchanged.

- Beautified bash step summaries (collapsed fold row only), in two decorations: command words get tinted chips — the first command of every separated segment (env assignments like `FOO=1` don't count and keep the expectation alive) plus its subcommand for known multi-word tools (`npm run`, `git commit`, `cargo build`, …), with boring text/file utilities (`ls`, `head`, `tail`, `rg`, `sed`, `cat`, …) left plain — while abbreviated tokens render dimed italic: a leading `cd <dir> &&` folds by its relation to the cwd (under it → `cd dir`; equal to it → no-op `cd;`; outside it → `cd …last/two &&`), and any path-shaped word with more than two real segments folds to its last two. The rules now run over a quote-aware piece scanner (new `scanShellPieces` export) instead of regexes over the raw string: quoted spans are opaque (separators and paths inside `"…"`/`'…'` are never decorated — `rg "foo|bar"` no longer chips phantom commands), and `&&`/`;`/`|` only separate when unquoted. Ad-hoc heuristics, no shell parsing; abbreviations carry the original on hover, the raw command stays the aria label, and the expanded card's identity line still shows the command unmodified.

- Action group headers name only the changed files, and pull less: the collapsed label lists edit/write basenames together under one category plus counts (`edit: a.ts, b.ts · run 2 tools · read 3 files`) — the bash key command (and its `2>&1`-mangling `extractKeyCommand` split) is gone from the header, and every non-edit/write tool renders as a count, needing no arguments (edit vs write stays visible in the expanded step rows and card identities). Thinking no longer appears alongside tool categories (a thinking-only group still shows a `think` fallback so the fold row isn't a bare triangle). The group-level `arguments` pull is restricted to edit/write steps; per-step argument wants moved into `ToolActionStepView` (mirroring `ThinkActionStepView`), so expanded rows keep their live summaries while collapsed groups fetch nothing for bash/read steps.

- Text selection now follows the chrome/content split: interactive surfaces (Launcher instance rows, Sidebar instance/session rows, History graph rows, TopBar title/buttons, toasts, composer pickers and path completion) are `user-select: none` so taps and double-clicks don't flash document-style selection; copy targets stay selectable — Launcher row cwd paths and message previews explicitly opt back in, and conversation content is untouched.

- Assistant Copy is attached to messages, not turns: each assistant text segment carries its own Copy chip (same `.toolbarBtn` style as the user-message Copy, floating at the segment's top-right, hover/focus-revealed, always visible on touch, hidden for empty text), and the assistant turn-header Copy is gone — a run-merged turn holds several messages, so there is no single "turn text" to copy. User turns are unchanged (header toolbar Copy).

- Turn structure reverted to run granularity: consecutive assistant entries merge into one turn again, and text blocks never split a turn — the per-message split from 8386faacf multiplied assistant turns ~5x on real sessions (54 → 271 on the before-compaction fixture). `segmentBlocks` already renders interleaved text and action groups in order within a turn, so the split's visual goal (keeping tool cards out of message turns) cost 5x the turns for a cosmetic gain. `turnKey` (now always `entryId`), per-turn timing windows, context-usage reporting, and error-line attachment (stopReason/errorMessage on the run-closing turn) are unchanged.

- Bash cards no longer auto-expand with truncation. New three-state progression (mirroring the edit card's cap logic): folded band = one-line command (the 5-line tail preview is gone from the band); expanded = status line + command identity + `… N earlier lines` + the last 20 output lines (line-count cap, no inner scroll window); "show all" = command plus the whole output, unbounded. Applies to the bash/powershell tool cards and the user-bash card alike.

- Launcher instance rows are now ordered newest-activity-first (client-side `sortByLastActivity`): the daemon still sends registry order, instances without a parseable `lastActivityAt` sort last, and ties keep input order so the 5s poll refresh never reorders equally-active rows.

- `InstanceInfo.preview` from `listInstances` now carries the most recent message text (any role, last one with a text block) instead of the first user message, so the launcher row shows where the conversation currently stands. The daemon-side extractor skips text-less messages (tool-call-only assistant turns); `lastActivityAt` still tracks the newest entry of any kind.

- `Daemon` holds a `Map<managerId, Manager>` registry instead of a single `manager` field.
- `listSessions` is scoped to the attached instance's cwd and filters out live sessions.
- `listFiles` takes an optional `cwd` parameter for per-instance path completion.
- `manager.dispose()` now awaits `session.abort()` before emitting `onExit` and tearing down the runtime (ensures "save first, then tear down").
- Web client `useConnection` fetches `listInstances` + `getDaemonInfo` on connect, and re-attaches via `switchInstance` if the stored instance id is still alive.
- `useConnection` auto-seeds at zero live instances: on connect with no live instance and a non-empty cwd allowlist, it creates one instance per allowlist cwd — each resuming that cwd's most recent prior session (fresh on first use) — and attaches to the last. The Launcher's empty state is now only reached when seeding fails or the allowlist is empty; >1 live instance still lands on the Launcher for picking.
- Web client reorganized into a layered structure under `web/src/`: `app/` (shell — `App`, `main`, `index.css`, `ToastBar`), `infra/` (`store` + `client`/`useConnection`/`useRpc`/`pullLoop`/`wants`), `render/` (`markdown`/`CodeSnippet`/`shiki`), and `features/<area>/` (`topbar`, `sidebar`, `conversation`, `composer`, `history`). `App`, `ConversationArea`, and `Composer` split into per-component files with co-located `.module.css`; `useConnection` split into `client` (singleton), `pullLoop` (wants-outbox drain), `useRpc` (verb wrappers), and `useConnection` (WS lifecycle). Pure reorganization — no behavior change.

- Composer commit is now atomic: `handleCommit` clears the draft only after the prompt/navigate RPCs resolve `ok`, so a failed or offline send leaves the text intact for retry. The previous flow cleared the textarea before the RPC could fail (permanent loss on disconnect).
- Composer blur semantics: blurring an edit draft salvages the typed text as a compose draft if modified (`text !== initialText`), or discards to idle if unmodified — a no-op edit blur yields an empty bar, a modified edit blur preserves the text. The old behavior orphaned `editingEntryId` in the store while the local textarea text was lost on collapse.
- Store fields `editingEntryId`/`editingIndex`/`editingInitialText` replaced by a single `draft: ComposerDraft`; `setEditingEntryId` replaced by `setDraft`/`setDraftText`/`beginEdit`/`blurDraft`/`clearDraft`.
- `switchSession`/`newSession` RPC wrappers now refresh `listInstances` so the attached instance's current `sessionId` (used to key draft persistence) stays in sync after a session switch.
- Compact wire form for streaming appends: the WS transport (`Connection` on the host, `BridgeClient` on the client) now holds a stateful `CompactCodec`. Consecutive single-op `append` patches to the same path are emitted as bare JSON strings (no frame envelope); the decoder restores the append op before the mirror sees it. Upper layers (diff engine, `DocumentMirror`, `onPush`) are untouched. Cuts streaming-append envelope overhead ~12× (a 33K-token thinking stream: ~3.66 MB → ~300 KB on the wire). See `docs/06-component-model.md` §Push.
- `computeObjectDiff` now recurses into arrays element-wise instead of replacing the whole array atomically. A streamed array argument whose element string field grows by a suffix (e.g. an edit tool's `edits[].newText`) now emits `append` on the element sub-path — O(n) wire cost — instead of re-sending the whole array per token (was O(n²); the `edits` stream alone was ~8.67 MB for a ~10 KB final value).
- Consecutive `model_change`/`thinking_level_change` entries (pi writes them back-to-back on a model switch — `setModel` appends the model change, then the thinking re-clamp appends a level change) now collapse into a single `model_switch` system turn reporting the run's final state (last model, last thinking level; the level is omitted when the run didn't change it). The web UI renders it as one normal-case markdown line — `Model: **DeepSeek V4 Flash** (via DeepSeek, thinking high)`, keeping the divider rules on both sides — using the daemon's curated model display name and a new `ModelInfo.providerName` field (from pi's `Provider` registry, e.g. "DeepSeek"), instead of one all-caps divider per entry. `SystemTurn.detail` removed; new `SystemTurn.switchTo` field. `SystemTurnType` is now `"compaction" | "branch_summary" | "model_switch"`.

- The Project home (`/<projectId>`) is compose-only: the active-sessions and recent-history lists are gone from it — the home shows just the centered compose card, and Projects + active sessions are listed only at the global launcher (`/`). Project sessions are browsed from the sidebar. The client-side plumbing for the home's history page is removed with it (the store's `sessions`/`sessionsHasMore`/`sessionsNextCursor` slice, `appendSessions`/`replaceSessions`, `loadProjectHome`, `loadMoreSessions`, and the `listSessions` fetch on every Project-home open / failed-open fallback).

- App decomposed from a 613-line controller into a ~300-line shell plus three behavior hooks, no behavior change: `useViewModel` (infra) owns the store→ViewModel projection and cache (the 11-field hand-maintained cache key moved into viewmodel as `viewModelCacheKey`, beside `leafPathKey`/`leafStreamingKey`, so a new projected `Status` field can't silently miss the key; the hook also selects the whole document instead of reassembling it from eight primitive selectors); `useComposerCommit` (composer) owns the draft→wire commit/fork flow (compose prompt, edit-fork-via-navigate, optimistic clear + failure restore); `useKeyboardRing` (infra) constructs the full `AppKeyHandlers` set, with the j/k step math extracted as pure `nextFocusedTurnKey` (turn-key identity contract) and the notification icon as pure `liveActivityPhase`. All three viewmodel additions are exported and covered by new unit tests (`viewmodel-keys.test.ts`).

- Compose surfaces deduplicated: `useComposeCapabilities` owns the attachment + path-completion wiring shared by `ComposeDock` and `HomeCompose` (both read the same store draft, so it owns the value/onChange pair too) and returns a typed `Pick` of `ComposeCardProps` that both spread, keeping the card's explicit presentational interface. The home's completion source is now a named module-scope `NO_COMPLETIONS` instead of a fresh inline no-op per render.

### Fixed

- ADR 11 activation leak: a WebSocket that closed while its `openSession`/`newSession` RPC was still creating the pi runtime still got attached once creation finished, and nothing could ever release the dead Connection — the activation's GC never armed and the runtime leaked for the daemon's lifetime. `Connection` now tracks disposal and the daemon skips the attach (arming normal idle GC for the orphaned activation instead).
- HTTP static serving used a string-prefix containment check (`filePath.startsWith(root)`); because `join()` resolves literal `..` components, a raw request like `GET /../web-x/secret.txt` (curl `--path-as-is`) escaped into sibling directories of `webRoot` sharing its name prefix. The check is now the same path-boundary `isContained` rule the session scanner uses.
- Markdown typography no longer escapes shrunken host contexts: Streamdown hardcodes rem-absolute `text-*` utilities (inline code, table cells, `sup`/`sub`, `h1`–`h6`) calibrated for the 16px document baseline, so in 12px contexts (thinking prose, tool-card `.md` prose) inline code rendered at 14px inside 12px paragraphs and an `h1` at 30px. One global block of em-equivalent overrides (`web/src/app/index.css`) now scales them with the host — the 16px document is pixel-identical, mobile (14px body) follows the shrunken baseline — replacing the per-surface `.markdownContent code` / `.thinkBody code` ratios (ADR 07 styling invariants #2/#4).

- Tool failures now display: the skeleton's error strip renders the tool-result error text for every card kind (previously failed `edit` calls rendered the attempted diff with no indication of failure — the body never read the result).

- Launcher instance rows now head-truncate the cwd (CSS `direction: rtl` + `<bdi>` isolation) so overflow clips from the left and keeps the discriminative path tail visible; the full path remains in the row's title tooltip.

- Clicking the live session's stub row in the sidebar (a bare session id pushed by the `newSession` push, shown until the session file lands on disk) no longer creates a junk `<session-id>` file in the daemon cwd. `Manager.switchSession` treated the id as a file path, so `SessionManager.open` resolved `cwd/<uuid>` and wrote the conversation there; it now no-ops when the target is the already-attached live session.

- Model picker disambiguation: when two providers offered the same model id (e.g. "claude-sonnet-4-5" under both Anthropic and an OpenRouter-compatible provider), Ctrl+P cycling started from the wrong provider's slot, the composer ghost button showed whichever provider sorted first, and the picker highlighted *both* same-id rows. Root cause was `Status.model` storing only the id; it now carries the `{ provider, modelId }` pair. New pure viewmodel helpers `findNextModel` (cycle) and `isModelSelected` (picker highlight) key on the full pair.
- History pane: SVG verticals/fork curves were offset 8px from the DOM dots. Breathing room moved from `.content` (whose padding box is the origin for absolutely-positioned children) to `.scroll`, so SVG and rows share an origin and dots sit on line endpoints.
- History pane: lane width narrowed (40→24 px) so multi-branch graphs no longer dominate the pane or truncate the label column on mobile.
- History pane: the "current" dot now marks the deepest on-path user message (stable across assistant turns) instead of only matching when the leaf was itself a user message.
- History pane: the drafts toggle badge was click-through — `.label`'s `pointer-events: none` was inherited by the badge, so clicks fell through to the row (navigating instead of toggling). The badge now re-enables pointer events.

- Edit-mode blur orphaned the editing pointer: the dimmed branch stayed in the conversation while the textarea text (local React state) was lost on collapse, leaving the view dimmed with no backing text. The draft is now the single source of truth for both dimming and the textarea.
- Sending while disconnected permanently lost the input: `handleSend` cleared `input` before the (no-op, disconnected) RPC fired. Commit is now atomic — the draft clears only on RPC success; a connection pre-flight toasts and keeps the draft.
- Closing the tab with unsent text neither warned nor remembered: a `beforeunload` listener now warns, and compose drafts persist to per-session `localStorage` and restore on reload.
- Composer input not resetting after a successful send: `Manager.prompt` awaits the *whole turn*, so clearing the draft only after the RPC resolved left the sent text in the textarea through the entire stream. The commit now clears the draft optimistically (before the RPC await) and restores it on failure, so the textarea empties immediately and a failed/offline send still keeps the text.
- Edit mode not exiting on blur when the bar was already expanded: `beginEdit` set `composerExpanded: true` but the focus-on-expand effect (deps `[expanded]`) didn't re-run when expanded was already true, so the textarea never gained focus — a later click-away couldn't blur it and `blurDraft` never ran. A second effect now focuses the textarea when an edit begins.
- Removed the `commitInFlightRef` Enter-dedupe: it blocked steering during a turn (the "RPC latency" it guarded is the whole turn). The optimistic clear makes a second Enter a no-op (empty draft), so the dedupe is both unnecessary and harmful.

### Removed

- `Daemon.prompt()` method (no single manager to prompt; prompting goes through Connection RPC).
- `liveSessionId` from `GetDaemonInfoReply` and the Zustand store.
- `activeSessionId` and `liveSessionId` store fields (replaced by `attachedInstanceId`).
- Daemon auto-creates a Manager on `start()`.
- Warmup session-cache scan on daemon start (no default cwd to scan).
- `--fixture` CLI flag (silently ignored after manual-creation-only change).
- `activeSessionId` field from `ViewModelInput` (unused vestigial field).
