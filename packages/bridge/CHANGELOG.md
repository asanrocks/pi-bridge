# Changelog

## [Unreleased]

### Breaking Changes

- The Daemon → Worker boundary is now the whole execution boundary, not only the Session one: `WorkerService` extends `WorkerEnvironment`, which adds `info()`, `setModelPinned()`, and the repository surface (`listFiles`, `readFile`, `listDirectory`, `gitShow`, `gitBase`, `gitDiff`). The Daemon no longer owns a `ModelRuntime`, per-Project `SettingsManager`s, the global `enabledModels` scope, or any repository read: those belong to the Worker, because a remote Worker's filesystem and catalogue are not reachable from the Daemon. `DaemonVerbs.listFiles` consequently returns a promise, and `DaemonOptions.modelRuntime`/`managerFactory` are in-process Worker seams rather than Daemon state.
- `WorkerEvent` gains `pinned_models_changed`, so the Daemon serves the global pinned list from the Worker that owns the scope instead of re-resolving it locally.
- Observation ownership is mandatory on the wire (ADR 19): `generation` is a required field on `ReplaceMessage`, `PatchMessage`, `SessionClosedMessage`, and `PullReply` — every observation frame names the attachment that produced it, and a frame without one is a protocol violation the client drops. Transport compaction pays for it without losing ownership: the codec is envelope-preserving (`core/compact-codec.ts`) — a run of live patches that differs only in the appended string sends that string alone as a bare JSON string, and the decoded frame is the identical envelope, generation included — so a frame after an attachment change can never match the stale template and compaction across an attachment change is structurally unrepresentable. The client rules tighten accordingly — `BridgeClient` drops a live patch unless the mirror's established generation matches exactly (a mirror with no established observation admits nothing), the pull loop drops a reply whose generation does not match the mirror's, and the view actor's re-assert and `session_closed` paths require the committed generation to match (a null committed generation commits nothing). The initial-sync frame the Manager emits is now a distinct pre-wire type (`InitialSyncFrame`); the observing Connection stamps the generation (and a creation's `operationId`) onto the wire envelope, so the core frame carries content only.
- `newSession` requires an `operationId`, and creation is a navigation-owned transition. The request carries `operationId: string` (minted by the navigation reactor), the host stamps it onto the transition's initial-sync frame (`ReplaceMessage`/`PatchMessage` gain an optional `operationId`) and the reply, and a missing id is refused (`Missing \`operationId\``) — an unattributed creation cannot be admitted by a selection owner. `BridgeClient.newSession` takes the id as a required option field; raw clients that omit it now fail. On the client, `navigationCreated` is gone: `navigationCreate(projectId, text, options?)` owns the whole creation (RPC effect, attribution, commit), and an initial-sync frame without an `operationId` can no longer select a new address through the no-pending path — it may only re-assert the already-rendered address.
- `EntryBase.id` is stable identity: an entry keeps its id from its first event through persistence and reopen, so sealing no longer emits a `move`. `EntryBase.isSealed` (absent means sealed) is the lifecycle fact; `pending:`-prefix checks and `migrateExpandKeys`/`migrateFocusedTurnId` are gone.
- `reconcile` and `ReconcileOptions` are removed from the public API. `createEntryProjection` (`src/core/projection.ts`) is the sole entry lifecycle: its `refresh` installs pi's appended suffix under each entry's own id (including silent appends and wholesale list rewrites), and its `settle` drops live forms that never persisted. Status-drift repair (`/status/model`, `thinkingLevel`, `contextUsage`, `recoverableTurn`) is owned by the Manager's refresh boundary, whose behavior is unchanged and pinned by the manager verbs suite (including a same-model-id/different-provider regression moved from the removed core tests).

### Added

- Browser chrome and the status bar now blend with the top bar. `web/index.html` carries a `theme-color` meta pair split by `prefers-color-scheme` with the `--color-sidebar` values (`#f0ede8`/`#242119`), so the Firefox/Chromium toolbar tint — and, in installed Chromium apps, the status bar — follows the app's ladder; the manifest's `theme_color` moves from the page tone to the chrome tone for the same reason. Installed iOS web apps get `apple-mobile-web-app-status-bar-style: black-translucent`: the web view extends under a transparent status bar and `PaneShell`'s existing `env(safe-area-inset-top)` padding lets the top bar paint that strip. Normal Firefox browsing is unchanged — the OS status bar there belongs to the browser, not the page. `docs/web/design.md`'s token-boundary rationale is updated; it previously documented the deliberate absence of `theme-color`.
- The actor ownership model (ADR 19) is implemented and merged, and the record is retired per the doc lifecycle. Every slice landed across this cycle: the contracts and characterization suites; the Session actor absorbing `session-execution.ts` and `session-lease.ts`; the registry thinned to addressing; the Connection split into the protocol adapter and typed verb modules; observation frames tagged with the attachment generation; the navigation reactor as the browser view actor; the value-only cache restore with the single-owner cache base; the actor's fully private runtime (`metadata()` as the daemon's only read surface); the registry's records free of runtime state; mandatory observation generations on the wire (with transport compaction retired); the view port as the actor's typed store/route seam; and the cross-layer lifecycle trace plus the streamed-payload load bounds pinning the invariants end to end. The ADR's current truth lives in the permanent docs — the architecture invariants and async owner inventory, the host runtime's Session actor and registry sections, the core protocol's generation rules, and the web architecture's view actor and port — and `docs/adr/0019-actor-ownership.md` is deleted; git history retains its rationale and rejected alternatives.
- The cross-layer lifecycle trace harness (`test/suite/lifecycle-trace.test.ts`) drives the whole stack against the real Daemon over faux-provider Managers, a real `BridgeClient` on a real WebSocket, the real connection pipeline, and the real navigation actor, asserting the invariants that must hold across interleavings: the mirror projects the canonical Document after attach, stream, seal, switch, and reconnect; a streaming Session left by a switch never repaints the successor's view (the attachment generation rule, exercised through a real reattach rather than an injected frame); a `closeSession` reply implies the runtime was disposed exactly once and the dead observation delivers nothing afterwards; a reconnect resumes through the cache cursor (the delta initial sync, not a full replace) and converges; and a daemon shutdown during a streaming turn drains before it resolves. To make the client stack runnable in the suite's Node environment, the application store singleton moved from `store.tsx` into `store.ts` (the React context re-exports it), and the pipeline's rAF/visibility coalescing became an injected `FlushScheduler` seam (`connectionPipeline.ts`; the browser implementation is `browserScheduler.ts`, passed by `useConnection`) — the pipeline module is now DOM-free.
- The actor ownership contracts (ADR 19, Proposed): the Session, Connection, and browser view lifetimes each spread their ownership across several modules whose state must agree after every `await`, and the fix history is almost entirely seam races between them. The refactor gives each lifetime one actor — a serialized owner built on the reactor — reached only through typed capabilities, and this slice defines the target seam with no behavior change. `src/host/session-actor.ts` adds `SessionCapability` (identity, the two admission classes, observation registration, a joinable release) and `ObservationCapability` (an independently releasable observation), adapted onto the existing `SessionExecution` so the characterization suite pins today's machinery through the seam the actor will occupy: a command admitted before release completes against the runtime it captured, observation release is idempotent and per-observation, the terminal drain is joinable with exactly one disposal, and nothing is admitted or delivered after a release or the terminal boundary. `SessionExecution` gains a read-only `ended` for the synchronous observation guard. `web/src/infra/net/viewEvents.ts` defines the typed observation events the view actor will consume — initial sync, patch, and session close, each tagged with the attachment generation that produced it — with `isCurrentGeneration` as the one comparison that drops a stale frame. The glossary binds **actor** and **capability** (the lease entry becomes the capability's, with the rename noted).
- The ownership-gate audit is retired: every finding landed with its regression promoted, the local work list is empty, and no `it.fails` marker remains. The owner inventory in the architecture doc is the surviving artifact — it now records the two rules the audit sharpened beyond "name an owner": externally visible work is admitted by a live intent (a superseded transition sends nothing; an attributed creation sync commits only while its operation owns the view), and terminal operations are joinable (a second caller awaits the in-flight disposal or the memoized drain rather than being answered by the terminal flag).
- `src/core/reactor.ts` is the serialized state-machine primitive behind the lifecycle ownership work: `createReactor()` applies typed messages one at a time in arrival order through a synchronous step function that returns the next state and may admit effects — asynchronous work whose completion returns to the reactor as an ordinary message. Admitted effects carry the epoch of the message that admitted them, so a superseded completion is rejected by one comparison in the step instead of a scattered "is this still current?" guard; `close()` stops admission synchronously and resolves only after every applied message, admitted effect, and their completion messages have settled (idempotent; every caller observes the same drain). Browser-safe, exported from the package root, and exercised by the curated browser-smoke entry.
- `src/host/session-execution.ts` is the work-admission owner for one registration's runtime. Commands are no longer run where they arrive: `setModel`, `setThinkingLevel`, `renameSession`, `setLabel`, and `navigate` enter one serialized mutation line (one at a time, in admission order, so concurrent commands from different Connections get a deterministic order), while turns (`prompt`, `recoverTurn`), `abort`, and reads (`pull`, `gitShow`'s cwd) run immediately but tracked. The two classes exist because the bridge must not add a competing turn lifecycle (architecture invariant 5): a Stop must reach a streaming turn rather than queue behind it, and a read that queued behind a turn would stall the live pulls issued while content streams — an earlier plan to serialize all commands would have deadlocked both. `end()` is the one disposal path: admission stops synchronously, queued mutations reject, the runtime is disposed exactly once, and tracked work is drained before it resolves; registry collection and daemon shutdown both go through it.
- The lifecycle ownership work is closed out as named invariants: a Connection reaches a Session only through a registry-issued lease (raw Manager access is a type error, not a convention); one SessionExecution per registration owns work admission; the navigation reactor is the single owner of browser selection; and async work is admitted by a named owner (LifecycleScope, reactor, or SessionExecution) whose terminal state drains before it resolves. The glossary binds **lease** and **reactor**; the architecture invariants list carries the rules. A full-lifecycle trace test runs one Session across two Connections — open, shared registration, a turn plus a concurrent lazy pull, collection settling the admitted turn with `session_closed` to both clients, a refused late command, and a shutdown drain — pinned in `connection-traces.test.ts`.
- `web/src/infra/net/navigation.ts` is the one owner of browser Session selection, built on the core reactor primitive: opening a Session, showing a Project home, leaving to the Launcher, and resolving `/@latest` are transitions of one state machine whose state is the committed view, at most one pending session transition, and the most recently superseded target. The step stages the target optimistically and admits the open RPC as an epoch-carrying effect; the address-bearing initial-sync frame commits the view (promoting the candidate mirror on a delta); the RPC reply confirms or rolls back. A completion whose epoch no longer matches is ignored with one comparison. This replaces the split flow where `useRpc` staged and hand-rolled rollback, `sessionBoot.openSessionAddress` ran the boot path with its own `isSuperseded` guard per await, and `connectionPipeline` committed addresses and routes from inside push handling — and it fixes two races the old flow had: a superseded open's initial sync previously committed its stale address over the successor (the serial-switch rule was an ignored request, not a supersede), and an open whose RPC failed after its initial sync had committed could still roll the committed view back. Boot failures land on the Project home and now clear the alias flag; `sessionBoot.ts` keeps only the cache-first local restore; the cache base moved to navigation (both halves of it seed it); `sessionCandidate` is promoted and discarded only by navigation.
- The Connection is now the serialized protocol actor for one WebSocket, with the two serialization domains stated and pinned: attachment transitions (`openSession`, `newSession`, `detach`) serialize among themselves in arrival order, and Session work serializes behind the lease's SessionExecution — the Connection adds no ordering of its own and owns no Session execution state. New cross-boundary trace tests (`connection-traces.test.ts`) run the real verb → ExecutionLink → registry path: a close during a running prompt settles the admitted command and then delivers `session_closed`; a switch completing under a running rename never retargets the command (its reply and broadcast describe the session it named); a pull reply describes the session it was issued against, not the one attached by the time it lands; and `session_closed` precedes the `closeSession` reply on the closing Connection.
- `src/host/session-lease.ts` is the Connection → Session capability: a Connection never holds a Session's runtime (the Manager) directly — `Connection.attach(Manager, …)` is gone — it holds a registry-issued `SessionLease` bound to one registration, and every session command, `pull` read, and `gitShow` cwd lookup runs through `lease.command`. A lease rejects commands once its registration ended (collection, replacement, or daemon shutdown), including the mid-collection window before the terminal `session_closed` push — previously a command arriving during disposal reached a Manager that was being torn down. A command admitted before its registration ended still completes against the runtime it captured, preserving the reply-describes-the-requested-session guarantee. The lease installs the Connection's observer handle (emitting the initial sync) at most once and removes it on release; the codec reset happens before installation, so a remembered compact-append path cannot leak across sessions. Tests attach through the same public capability (`issueDirectLease`) instead of a test-only Connection API.
- `src/host/execution-link.ts` is the seam between the Daemon and Session execution: the Daemon owns configuration, catalogues, scanning, broadcasts, and the wire surface, and routes every session-lifecycle verb (open, create, awaitSettled, collect, release, live, dispose) through the `ExecutionLink` interface. The local implementation owns the Activation registry and the per-session choreography (Manager creation, registration, the pre-attach model/thinking choices, first-prompt admission), moved verbatim out of the Daemon's `newSession` verb; behavior is unchanged. Every Activation registration now carries an authorization — the link's `incarnation` (one daemon run) plus the registration's `generation` within it, never reused — so work composed against a registration names an identity a replaced registration cannot inherit; in the local link a new generation is always a new Manager and a new attachment. A future remote link (the Worker/socket design of the feat-mux line) implements the same contract without the Daemon branching on locality.
- `src/host/repository.ts` is the repository and filesystem read surface extracted from the Daemon (~760 lines): snapshot reads, directory listings, the review diff directive, `git show`, the comparison base, and Project-cwd path completion — every spawn bounded and every wire argument validated before a process starts. Pure module move; the Daemon imports the same functions, and the test suites now import them from their owning module.
- `src/host/lifecycle-scope.ts` is the one shared implementation of the serialized-operation FIFO the host had three hand-rolled copies of: Connection's attachment-transition chain, the Daemon's settings-mutation chain, and the git-stamp observation queue. `createLifecycleScope()` runs operations one at a time in arrival order, swallows a rejection out of the chain so one failure never wedges the next, and has a terminal `close()` that stops admission synchronously and resolves only after admitted work settles (idempotent; every caller observes the same drain). Connection disposal now drains its transition chain — a transition queued behind disposal still answers `connection closed`, and daemon disposal refuses further settings mutations and waits out an in-flight flush.
- `src/host/activation-registry.ts` is the one owner of live-Activation state, extracted from the Daemon: creation (shared for concurrent opens, awaiting a collecting Activation before retrying), registration, attachment, idle collection, and the durable session-id ownership index, as one state machine (absent → creating → live → collecting → absent). The Daemon keeps only the pushes and the Manager factory, supplied as hooks; behavior is unchanged.
- Attachment-changing verbs (`openSession`, `newSession`, `detach`) are serialized per Connection: each runs to completion before the next begins, in arrival order. Concurrent transitions could previously run interleaved — a slow first open and a fast second both replied, and the last writer decided which Manager the Connection ended up attached to, so the reply the client trusted and the attachment the server kept were different operations' results. A disposed Connection now also refuses admission: a transition arriving after the socket closed, or reaching its turn after it, replies with an error instead of attaching something nothing would ever release.
- `src/core/projection.ts` merges the two inputs a Document has: live forms from session events and authoritative entries from pi's entry list. `createEntryProjection` installs persisted entries (content, metadata, `isSealed`, `ord`), never lets a delayed event overwrite a sealed entry, and drops live forms that never persisted at a settle boundary.
- The Manager reads pi's entry list through one refresh boundary before attach, after events, after its own verbs, and at settle boundaries, so silent appends such as labels reach clients and an event payload is never treated as proof that an entry exists.
- The conversation and history panes have a loading tri-state instead of asserting what the wire has not confirmed, and a session switch is instant. The store carries `docAuthority` — `authoritative` (an address-bearing initial sync, `commitObservation`; live patches extend it), `seeded` (this address's own last-known state painted from the cache, via the new `paintLocalDocument` store action), or `staged` (not this address's document: an optimistic address change without a cache for the target, or the teardown's empty placeholder). A navigate's `prepared` step now paints the target's cached prefix into the store (the instant switch — the previous conversation is replaced at once, not kept under the new address), skipped when the committed view is already the target so a re-navigate cannot downgrade the live document to a cache snapshot; a failed navigate's rollback re-commits the restored view's address pair through the new `commitAddress` store action, repainting the mirror's committed root so the paint's snapshot does not survive the failed switch. The projection takes `authoritative` as an input (default true — the pure projection trusts its caller; `useViewModel` passes the store flag, and it joins `viewModelCacheKey`). Unconfirmed + empty renders a turn-shaped skeleton (a user-tinted row and assistant text lines on the shared liveness keyframes) instead of the empty-state copy. A seeded document renders its content with the same skeleton continuing after the last message — visibly not finished, asserting no failure — until the initial sync commits. A staged document renders untouched: appending the new session's wait to the previous session's conversation on screen would mis-attribute it. The history pane's graph follows the same rule on its own empty state, and the collapsed compose bar's status dot shares the loading state: orange (the shared in-flight hue) while the document is unconfirmed, not just while a turn streams.

### Added

- The Worker can run as its own process. `src/host/worker-protocol.ts` is the only encoding of the `WorkerService` contract (correlated requests/replies, observation-tagged frames, Worker events, and a terminal `unavailable`), `src/host/worker-server.ts` serves one service over a socket, `src/host/worker-client.ts` implements the same contract as a Daemon-side client with heartbeat liveness, `src/host/worker-process.ts` is the Worker role, and `src/host/worker-host.ts` is the deployment seam that produces a Worker in-process, by connecting to a running one, or by spawning a child. The child runs the same binary (`--worker-serve --socket <path>`, internal plumbing — not part of the role model), so a single-file install needs no second entry point.
- The CLI takes an explicit role over a discovery socket. `pi-bridge` (auto) probes the socket (`--socket`, default `$HOME/.pi/bridge.sock`) and joins a live daemon as a Worker, else starts a daemon that hosts one Worker in-process; `--mode=daemon` serves the web app and registered Workers only and fails when the socket is already owned; `--mode=worker` registers this invocation's Projects with an existing daemon and fails when none answers (`--daemon <ws-url>` for a remote one). Losing the socket bind race joins the winner. A stale socket file is removed only after the probe proves it is a socket nothing listens on; a path that is not a UNIX socket is reported, never removed. `src/host/daemon-socket.ts` serves the probe and the dial-in registrations (a Worker dials the Daemon; the Daemon never dials out for a local registration), and `src/host/discovery.ts` holds the role decision. A dial-in Worker keeps its runtimes across a Daemon restart and re-registers with bounded backoff.
- Registration is the Project-claiming authority. The Worker's `hello` push carries its `WorkerRegistration` and `WorkerInfo` before any reply; the Daemon accepts the set all-or-nothing (empty, duplicate, or reserved-id collisions close the link) and the accepted set is its routing table, so a Project outside it answers `Unknown project`. A protocol-version mismatch is refused rather than parsed. A lost link withdraws the registration and stops advertising its Projects without killing the Worker's runtimes, and a reconnecting Daemon is a new registration.
- Session-directory exclusion for cross-process execution (`src/host/storage-lock.ts`): an exclusively created lock file per Session directory holding the owner's pid, host, and a random token, held by the Worker for its lifetime and released only by its holder after every runtime is disposed. Reclamation is limited to a provably dead same-host owner; a foreign-host claim is never reclaimed, and that limitation is documented rather than hidden. A Worker that cannot claim its directory fails to start rather than writing JSONL unsynchronized.
- `startLocalWorker` builds the environment the Worker owns (model runtime when not injected, extension-registered providers, per-Project and global settings, storage claims) and is now the entry both the Worker process and the in-process Daemon use.

### Changed

- A message the client cannot decode or does not recognize is never silently tolerated. `BridgeClient` surfaces malformed JSON, a compacted frame with no established run, a non-object frame, and an unknown push kind through the new `BridgeClientOptions.onProtocolError` (fired once per client) instead of the old silent `catch { ignore }`, and the web client toasts (`Incompatible message from the daemon (…) — reconnecting; if it repeats, reload the page.`) and closes the socket, so the reconnect path's initial sync repairs the stream. The wire carries no version negotiation by design; the accepted cost is the upgrade window — a tab left open across a daemon upgrade speaks the previous dialect, and its transcript may stall mid-stream until the page is reloaded.
- The Daemon registers several Workers and routes by Project. `DaemonOptions.workerModes` replaces the single `workerMode`: the accepted registrations form one routing table (a Project id is served by exactly one Worker), a conflicting claim fails startup and disposes the registrations created so far, and an unavailable Worker withdraws only its own Projects while the rest keep serving. `getDaemonInfo`, `listActiveSessions`, and pinned-model pushes report the aggregate, deduped by identity; repository reads route to the registration whose Project cwd contains the path.
- `unavailable` is terminal on both ends of the Worker link. The Worker stops admitting requests and ends the connection's observations when it reports one; the client settles pending requests, delivers a `closed` frame for every live observation, and takes the socket-failure path. Previously the push was advisory: pending requests waited for replies that could never arrive and the browser kept an attachment that could not progress.
- Worker shutdown drains before it answers: request admission closes synchronously, admitted dispatches are tracked and awaited, and only then is the reply sent and the service disposed. A request arriving after admission closed is dropped rather than starting work nothing owns.
- An observation acquired while its socket is closing is released by the acquisition instead of being installed on a dead connection, so a disconnect during `observeSession`/`createSession` can no longer pin an Activation with no owner left to release it.
- pi-core's offline mode (`PI_OFFLINE`/`PI_SKIP_VERSION_CHECK`) is established by the Worker startup path rather than the Daemon, so a standalone `--worker-serve` process is offline too; previously only the embedded path set it.

- The browser view actor's decisions are separated from store publication (ADR 19): `web/src/infra/net/viewPort.ts` is a typed seam — `NavigationViewPort` — that is the complete inventory of what the navigation actor may read (the rendered address, the published session id, the rendered document facts) and write (stage, commit, restore, clear, paint, route, alias flag). The actor's steps call the port instead of touching the Zustand store, the history API, or the address index; those mechanics live in one adapter (`createNavigationViewPort`), injectable through `NavigationDeps.port`. The local-seed race guard, the close/rollback decisions, and the re-assert checks now read one owner's publication through the port instead of reaching into the store. Pinned in `viewPort.test.ts`: an observation commit is one store write (a subscriber never sees a new address paired with the old document or id), a restore republishes the trio together, a clear retains the Project it lands on, and the alias flag keeps the URL in alias form across a commit.
- The Activation registry is addressing only, and the record's last runtime-state duplicate is gone. `ActivationRecord.lastStreaming` is deleted together with the registry's `manager.onPatch`/`onSettled` wiring: the Session actor observes its own runtime's settlement and streaming transitions (`SessionActorOptions.onSettled`/`onStreamingChange`, deduped by the actor) and relays the daemon's broadcast hooks, so the registry's records carry no runtime state — they hold the actor, the attachment set, and the collection reservation, nothing else. The registry's exclusivity matrix is pinned directly in `test/suite/activation-addressing.test.ts`: concurrent opens share one creation, an open arriving during teardown waits for the completed disposal (the address stays reserved while the runtime dies), a stale record can neither dispose a replacement nor release its durable-id claim, a durable session id is claimed by only one address, `awaitSettled` sees a creation still in flight, and a shutdown drain disposes a Manager whose factory completed mid-drain.
- The Session actor's runtime is fully private (ADR 19's final migration slice): `SessionActor.manager` is gone from the public surface, and the daemon's listing reads (`scanProjectSessions`, `listActiveSessions`, `toSessionInfo`) go through the actor's new `metadata()` — the typed facts derived from the canonical Document (`ActorMetadata`: session file, creation time, streaming flag, name, message count, and the preview fields previously computed by the daemon's `documentSummary`, which moved into the actor module). Raw Manager access now exists only in the creation paths (the factory, the stem derivation, and the pre-attach choices in the ExecutionLink's fresh-session choreography) — the pre-live window the actor's header documents as the one sanctioned raw access, because the runtime has no owner to admit work through until the actor exists.
- The cache-first restore is value-only, and the cache base has one owner (ADR 19). `restoreLocalSession` (`sessionBoot.ts`) no longer writes the store: it returns the seed — the address, the durable session id, and the quiesced seeded document — and the view actor decides whether the values become visible: `useConnection` hands the seed to `navigationLocalSeed`, whose `localSeed` step applies the store-based race guard (unchanged semantics: a stale cache read can never overwrite wire data) and paints. The cache base is no longer an exported mutable box the pipeline mutates: it is navigation's private state, seeded by the actor's steps and read/advanced by the pipeline's write-through through `cacheBaseDocFor`/`advanceCacheBase`. The sessionBoot suite now drives both halves of the flow (the value-only read and the actor's decision) with the same assertions.
- The navigation reactor is the browser view actor (ADR 19), and observation delivery into it is typed. The connection pipeline now hands over `ViewObservationEvent` values (`viewEvents.ts`) through one seam — `navigationObservation` — instead of calling `navigationInitialSync`/`navigationSessionClosed` (deleted); it decodes the wire and decides nothing. The actor's state gains the committed attachment generation: the sync that commits the view records the frame's generation, an unattributed re-assert from another generation never commits — same address or not, closing the gap where a stale attachment's frame could re-assert the rendered address — and a stale-generation `session_closed` never ends the view (a close of the current attachment still does). Frames without a generation (legacy hand-built frames, a restored pre-generation view) keep the address rule alone. Pinned in `navigation.test.ts` (stale re-assert dropped, current re-assert admitted, stale close ignored, current close lands).
- Observation frames carry the attachment generation (ADR 19). Every Connection mints one generation per attach, and every observation frame names the attachment whose stream it belongs to: the initial sync (`ReplaceMessage`/`PatchMessage` gain `generation`), live patches, the terminal `session_closed` (`SessionClosedMessage` gains it; the registry now sends it through `Connection.pushSessionClosed`), and `pull` replies (`PullReply` gains it, stamped with the generation captured at handler entry). On the client, `DocumentMirror` records the generation an address-bearing frame establishes, and `BridgeClient` drops a live frame from an older attachment before the mirror — and before `onPush`, so no publication or cache write happens either — even when the address is unchanged; the pull loop drops a reply whose generation the mirror advanced past (a reattach on the same socket), alongside its existing stale-client and seal guards. Compact (bare-append) frames carry no generation and stay admissible: they cannot cross an attachment change, because attach resets the codec. Pinned in `bridge-client.test.ts` (establish, drop, lenient), `connection-daemon.test.ts` (increasing generations on reattach, the close's stamp), and `pullLoop.test.ts` (stale reply dropped).
- The Connection is the protocol adapter, and its verbs are typed handler modules. `src/host/connection-verbs.ts` now holds the `DaemonVerbs` seam (moved from `connection.ts`) and one seam function per verb: each validates the request shape, captures its target at handler entry — before any await — and replies through a `VerbContext` that exposes only the daemon seam, the attachment capability, subscription registration, and the reply path (no socket, no transition state, no runtime). The three attachment transitions (`openSession`, `newSession`, `detach`) stay in `connection.ts` — they are the serialized transition line itself — and the message handler reduces to that line plus a table lookup. Session handlers no longer touch a runtime at all: the capability gained typed verbs (`prompt`, `abort`, `discardSteer`, `setModel`, `setThinkingLevel`, `renameSession`, `setLabel`, `navigate`, `recoverTurn`, and `pull`, plus a `cwd` identity field), admitted through the actor's two admission classes; `pull` returns each value with a `live` flag so the handler — not the runtime read — owns the subscription side effect, and the generic `command`/`mutate` admission remains for reads and tests. Wire behavior is unchanged (same validation, same replies, same ordering), pinned by the Connection suites over the real verb paths and new actor cases for the typed verbs and `pull`'s live reporting.
- The Activation registry is the index and reservation layer around the Session actors, and the duplicated registration-lifetime state is gone. `record.ended` and `record.gcTimer` are deleted: the actor's phase is the terminal fact (`collect` invokes the actor's close synchronously before its first await, so every liveness check refuses the record from the instant collection begins, with no separate flag), and idle collection moved into the actor — a live capability is an attached client that keeps it alive and cancels its timer, the fire-time check defers while the runtime streams or compacts, and the ADR 11 policy delays (now defined once, in `session-actor.ts`, and passed through by the daemon) decide durable/empty versus entry-bearing unflushed. The registry keeps what is addressed rather than run: the address and session-id indexes, creation reservations, the attachment index, and the collection choreography (index cleanup plus the terminal `session_closed` notifications) that runs when the actor reports idle; `collecting` remains the registration's disposal promise — the actor's close plus the cleanup — that reservations and late collectors join, so an address stays reserved until both complete. The orphaned-creation path arms the actor's idle timer explicitly (`armIdle`). Pinned by the actor suite's idle-collection cases and the daemon's timing-based GC suites; the race and shutdown invariants (concurrent opens share one actor, open-versus-close exclusivity, refused late registration, durable session-id uniqueness) are unchanged.
- The Session actor (`src/host/session-actor.ts`) is the one owner of one Session's runtime lifetime, absorbing and deleting `session-execution.ts` (admission and the terminal boundary) and `session-lease.ts` (the Connection's release guard). An Activation record now holds the actor; the registry issues its `SessionCapability` to Connections (`attachCapability`/`detach`), and collection and shutdown terminate through the actor's joinable `close()`, with the phase state machine explicit (`live → closing → closed` in this slice; `creating` names the registry-owned creation window the registry thinning moves inside). Behavior is preserved — the two admission classes, the capture-at-entry rule, the one-disposal guarantee, and the reply-describes-the-requested-session guarantee are unchanged — with one strengthening: the actor's `close` releases every live observation after the drain, so the teardown's final patches still land while no observer handle outlives the actor. The capability replaces the lease with independently releasable observations and a joinable release; the characterization suite is `test/suite/session-actor.test.ts`, and the registry-, Connection-, and listing-level suites exercise the same seam through the real verb paths.

### Fixed

- A cache-seeded session no longer renders the synthetic "Interrupted before the reply finished" line while the initial sync is still in flight. The ADR 16 recovery derivation now runs only on a wire-confirmed document: a cache seed paints the quiesced last-known state, whose mid-run tail (tool calls answered, no final assistant) is exactly the `unfinishedTurn` shape — presented as a terminal interruption before the daemon had said anything. While unconfirmed, the continuation skeleton (above) renders instead; if the wire then confirms the interruption, the recovery row appears. Pinned in `viewmodel-unit.test.ts` (provisional input derives no recovery; the same document confirmed derives it) and `store-unit.test.ts` (the authority transitions).
- A dial-in registration the Daemon refuses for a Project conflict closed gracefully instead of with the rejected close code: the refusal path disposed the adopted link first (`closeLink`'s graceful close), so the code the Worker reads its verdict from was sent on an already-CLOSED socket — a no-op. The Worker mistook a terminal refusal for a lost link and reconnected against the same conflict forever, never exiting, while the Daemon logged nothing. The refusal (a Project id another registration already serves, a reserved surface name) is now sent while the socket is open and is logged; `closeLink` no longer terminates a close handshake that is already in flight, which is what stripped the code. A refusal during Daemon shutdown is the exception — it closes gracefully, so a Worker that dials in mid-shutdown retries the next Daemon rather than dying, and a Worker adopted while shutdown began no longer completes registration into a draining Daemon. Pinned in `daemon-socket.test.ts` (a conflicting registration resolves `closed` instead of retrying, exactly one link is made, and the first registration keeps serving).
- Both ends of a Daemon↔Worker link now heartbeat. Only the Daemon's client pinged, so a Worker serving over TCP (a remote `--daemon`) never noticed a hung peer: its registration stayed pinned with no reconnect, and an idle link produces no write that would fail. The Worker's server end now pings on the same interval and takes a silent peer through the same terminal path a socket error takes. Pinned in `worker-socket.test.ts` (a silent peer is terminated, an answering peer stays connected).
- Worker shutdown is finished before it is acknowledged, and disposal is joinable end to end. The protocol server replied to `shutdown` before disposing the service, and a spawned parent kills the child on that reply — so the child's `process.exit(0)` could beat the registry drain, cutting off a streaming turn's final flush and leaving the storage-claim files behind (reclaimable, but blocking the next start of that Project until then). The reply now follows the disposal, and `LocalWorker.dispose()` returns one memoized drain to every caller, so the socket shutdown and the Worker process's signal handler cannot race an exit past the runtime drain. Pinned in `worker-lifecycle.test.ts` (the reply arrives only after the service disposed) and `worker-local.test.ts` (a second `dispose()` awaits the in-flight drain).
- A Worker whose registration claim failed is disposed with the rest. The Daemon pushed a created host onto its cleanup list only after validating the advertised Project ids, so the registration that lost a claim to another Worker leaked: a spawned child stayed alive, holding its socket and its session-directory exclusion, and the next start of that Project failed on the live lock until the orphan was killed by hand. The host now joins the cleanup set before its Projects are validated. Pinned in `worker-routing.test.ts`.
- A stale terminal observation frame can no longer detach the successor attachment server-side. `Connection` cleared its attachment for any `closed` frame, without checking the attachment generation the frame carried — a `closeSession` of the session a switch just left, racing the switch's release of that observation, delivered its terminal frame after the successor was installed and detached it: the client (protected by its own generation rule) kept rendering the session while every subsequent command failed with `no session attached` until the next navigation re-attached. A terminal frame still always crosses the wire; only the current attachment's terminal frame ends the attachment. Pinned in `connection-traces.test.ts` for both directions (a stale close ignored, the current close lands).

- Stale-lock reclamation can no longer delete a live successor's claim. Reclaiming a crashed owner used a bare check-then-unlink, so two reclaimers could both judge the same record stale, the winner could create a fresh lock, and the loser's unlink removed that live claim — leaving two Workers writing one Session directory. Deletion now runs under an exclusively created `.pi-bridge.lock.reclaim` guard, re-reads the lock while holding it, and removes it only when it is still the record that was judged stale; the guard is released in `finally`, and a stale guard can only block acquisition, never permit a second holder.

- Streamed tool payload delivery is linear in the body, not quadratic in the update count. A `tool_execution_update` whose partial content progressively grows a single text body re-sent the whole accumulated body on the wire per update (~2 KiB × (1 + 2 + … + N) for an N-chunk stream), because the patch was a full `replace /entries/<id>/content` each time. The projection now emits a `lazy`-marked `append` carrying only the new suffix (a first update, a non-extending rewrite, or a multi-block body keeps the wholesale replace), and `AppendOp` gains the optional `lazy` flag: `filterPatchForSocket` withholds such an append from unsubscribed Connections exactly like the full-field replace it encodes, matching the subscription against the op's path and its ancestors. Measured through the real stack in `test/suite/load-bounds.test.ts`: a 50-update, ~100 KiB streamed body crosses the wire in well under 4× the body size (the quadratic encoding would be ~2.5 MiB), exactly one full-body frame remains (the tool's end), the store repaints at the flush cadence rather than the update cadence, one pull fills the sealed body, and the mirror converges to the canonical Document. The encoding and the filter rule are also pinned at the unit level in `document-unit.test.ts`.
- Manager teardown composes with observation teardown, and is joinable. `dispose()` previously awaited `runtime.dispose()` before draining the git-stamp observation scope, so a queued observation could still be running `git` — and appending — after runtime teardown began. The order is now: finalize the in-flight turn (whose boundaries may enqueue observations), stop event-driven admission, drain the observation scope (every drained observation appends to a live runtime), then dispose the runtime. `dispose()` is also idempotent and joinable (a memoized teardown, like every other terminal operation), so the harness's direct dispose and the registry's SessionExecution drain cannot interleave a second run. Pinned with a gated-runner integration test (`git-stamp-integration.test.ts`): disposal blocks while the observation runs, the drained stamp lands in the session, no git spawn starts after disposal resolves, and a second dispose joins the first.
- A creation's initial sync is bound to its owning intent. `newSession`'s address-bearing frame had no identity tying it to the operation that admitted it: with no transition pending it committed through the no-pending sync path, so a `newSession` frame could commit over a newer Project-home or session intent. The creation now carries an `operationId` (minted by the navigation reactor, stamped by the Connection onto the frame and reply, refused when absent), and the frame commits only while its creation is still the newest intent; an unattributed frame may only re-assert the rendered address. A creation also supersedes a pending open (which settles superseded without sending) and its reply commits defensively only while it still owns the view. Pinned in `navigation.test.ts`, `navigation-ownership.test.ts`, and a Connection trace that runs the real verb path (refused unattributed request, attributed frame and reply, unattributed plain open).
- Navigation commands are gated by intent ownership, not just their completions. A superseded open's prepare still sent its `openSession` RPC — the server serializes attachment transitions in arrival order, so a slow cache read could put the abandoned session's open on the wire after the successor's, leaving the connection attached to a session the UI no longer showed (and later commands targeting it). A superseded transition now sends nothing and settles its caller client-side (`superseded` — a silent no-op, no toast); an RPC admitted before the supersede still runs to completion and commits nothing. The Project-home and Launcher transitions likewise decide their detach from the staged intent (`pending ?? current`) instead of the committed view alone — the same window could leave the server attached to a pending open's session while the UI showed the Project home. And a `/@latest` resolution with no target settles its caller on every path — a user press could hang forever and a boot could stall `useConnection`'s connected handoff. Pinned in `navigation-ownership.test.ts` (three markers lifted) and `navigation.test.ts`.
- Termination is joinable, not just final. `ActivationRegistry.collect` answered "is it dead" (`ended`) instead of "has it finished dying": a second caller arriving mid-disposal returned immediately, so `archiveSession` could move a session file while its Manager was still flushing or aborting. `collect` now joins the in-flight disposal promise (cleared only when the disposal completed), and the registry's `dispose()` returns one memoized drain to every caller instead of returning on the terminal flag — the same join contract `SessionExecution.end` and `LifecycleScope.close` already have. The reactor's effect-error reporter is likewise wrapped, so a throwing `onUnhandledEffectError` cannot escape as an unhandled rejection beside a sound drain. Pinned in `ownership-gates.test.ts` (previously `it.fails`).
- The last unowned asynchronous site has an owner: the pull loop's retry timer was module-level and never cleared, so a backoff scheduled by a failed pull could fire after the connection it retried for was gone. `cancelPullRetry()` is its terminal — called at connection teardown, clearing the timer and resetting the backoff — and the connection pipeline's in-flight cache writes are gated on the pipeline not being disposed, so a dead connection writes neither the store nor the cache after cleanup. With that, every asynchronous site in the audited surface names an owner with a terminal operation; the architecture doc now carries the owner inventory as the checkable form of invariant 17.
- Host ownership termination is final. The git-stamp observation scope was never closed: host-triggered observations were fire-and-forget and `Manager.dispose()` did not drain them, so a queued observation could still be running `git` after disposal resolved. The bundle now exposes `end()` — admission stops synchronously, and `Manager.dispose()` awaits it after the runtime is torn down, so no `git` spawn starts after disposal resolves and a trigger observation cannot outlive the runtime it appends to. An `ActivationRecord` had no terminal state (`collecting` was a transient lock reset on completion), so a stale handle re-entered disposal and released the durable session-id claim by address-field comparison — deleting a newer registration's claim and letting a second address open the same durable id. `ended` is now set synchronously when collection begins and never reset: a stale `collect` is refused, the id claim is released by record identity, and every liveness check (`byAddressLive`, `live`, `reserve`, `attach`, GC) refuses an ended record. `Connection.dispose()` is now the awaited drain it always claimed to be — the daemon's teardown snapshots the Connections, stops the server, and awaits each transition drain before disposing Session execution.
- The async admission boundaries are normalized where they are created, so promise accounting cannot be defeated by a synchronous throw. A reactor effect whose `run()` threw synchronously incremented the in-flight count and never decremented it: `close()` never resolved (phase stuck at `closing`), and `onUnhandledEffectError` never fired, so the effect bug was silent. The effect call is now normalized inside the reactor — a synchronous throw decrements the count and is reported exactly like an async rejection, and `close()` still drains. `SessionExecution.run()` had the same shape: an operation that failed before returning its promise escaped as a synchronous throw instead of the rejection every caller handles, leaving the work untracked; it now rejects. Both are pinned as regressions (`reactor.test.ts`, `session-execution.test.ts`).
- Closing a session left its attached Connections holding the disposed runtime: `closeSession` and `archiveSession` disposed the Activation and severed only the registry's bookkeeping, so a client kept its attachment, later session commands reached a disposed Manager, and the view could stall until a reconnect re-resolved the address. Collection is now the terminal ownership boundary: every attached Connection is detached (Manager handle and attachment fields severed) and receives a new `session_closed` push (`projectId`, `stem`) after the disposal's final patches and before the close reply; a session command that arrives afterwards fails with `no session attached`. The web pipeline clears to the Project home — the same boundary a failed open uses — when the closed address is the rendered Session, and ignores a close of some other Session.
- A lazy-pull reply could be filled into content that had already been superseded: the reply is a read of the moment the request left, so a pull issued against a streamed entry could land after that entry sealed under the same stable id, writing the older streamed value over the persisted content with no later patch to repair it. The same held for a field a live patch had already filled with newer content. A reply is now admitted only for an entry whose seal state is unchanged since the request and only into a field that is still unfetched, so it can fill what nothing else delivered and never overwrite a newer publication.
- Two concurrent `setModelPinned` calls could silently drop one update: the verb is a read-modify-write over the daemon-global `enabledModels` scope, and each call read the pre-mutation list, so the later flush lost whatever the earlier one had written. Settings mutations are now serialized daemon-wide — one at a time, in arrival order, across every Connection — and the chain swallows rejections so a failed mutation cannot stall later ones.
- The dev-mode console relay hooked `console.log`/`warn`/`error` once per successful connection without ever restoring them: after N reconnects each browser line was relayed N times, through every client the page had ever had, including dead sockets. The hooks are now installed once per page and repointed at the current client, and unhooking on connection close or teardown restores the original methods.
- The document and its revision were published as two separate store writes, and the publishers outside the wire pipeline (`restoreLocalSession`, cache seeding, lazy-pull ingestion) never moved the revision at all: a cache-first boot could restore a cached document that differed from the prior paint only in content the structural ViewModel key cannot see (same ids, same lengths — a changed label or tool name) and keep rendering the stale ViewModel. `applyReplace(doc, revision?)` is now the one publication action: the wire pipeline passes the mirror's revision, every other publisher advances the store's own counter, and a document can no longer be published without its revision moving. `setDocRevision` is gone.
- Fresh-session creation ran outside the activation registry's shutdown drain: `newSession` called the Manager factory directly, so a factory still in flight when `dispose()` began completed afterwards, and the registration it attempted was refused with a fire-and-forget disposal — the drain had already returned while the late Manager was still shutting down. The whole Manager-owning phase (creation, registration, pre-attach model/thinking choices, first-prompt admission) now runs as one registry-tracked creation (`ActivationRegistry.runCreation`), and a registration refused because shutdown began awaits the Manager's disposal before throwing, so the drain cannot return before that disposal finishes.
- `closeSession` and `archiveSession` acted on the registered activation state only, so an address with a creation still in flight was invisible to them: a close answered "not active" while a Manager was being constructed (leaving the address live right after a successful close), and an archive moved the file underneath the completing creation, registering a Manager for an archived address. Both verbs now wait out a creation in flight for the address (`ActivationRegistry.awaitSettled`) before acting. Reserving and attaching also became one registry operation (`ActivationRegistry.open`): a close that lands between an open's reservation and its attach makes the open re-reserve instead of attaching a collected record, and the registry refuses to attach a collecting record outright.
- A lazy-pull reply could outlive the state it was issued against and corrupt the successor view. A reconnect replaced the global client while the reply was in flight, and the pull loop still published the dead socket's mirror into the store; a session switch on the same socket replaced the mirror, and `ingestPullResponse` wrote the old session's entry paths into the new document — `setAtPath` auto-creates missing parents, fabricating the old session's entries inside the successor. A reply is now admitted only while its client is still the global client and its entry ids survive in the current mirror (entry ids are unique per session, so a surviving id means the pull's session is still the mirror's). Dropped replies schedule no retry: the replace push that re-establishes the view bumps `pullTick`, and visible fields re-register.
- Daemon shutdown cleared the activation registry without draining it: a Manager factory that was still in flight could complete after `dispose()` and register an Activation nobody owned — a live Manager leaked, and its session appeared in the active snapshot after shutdown. The registry now has a terminal state: `dispose()` sets the flag and clears every index in one synchronous block, then awaits in-flight creation promises (whose registration is refused, disposing the Manager the factory produced) and in-flight collections before disposing every remaining Manager exactly once. After the flag, `reserve`/`register`/`attach` refuse and `collect`/`armGc` are no-ops, so nothing registers or double-disposes after shutdown. `dispose` is idempotent.
- A session command could be retargeted by a transition that completed while it ran: `renameSession` read the attached SessionRef after its await, so the `sessions_changed` broadcast went to the successor session's Project when an open completed mid-rename. Every attached-Session verb (and `pull` and `gitShow`) now captures its target Manager and SessionRef at handler entry, before any await, so a command executes against — and reports on — the session attached when the request arrived.
- `BridgeClient` sent an RPC request before installing its pending reply record, so a transport that answered inside `send` (an in-process link) delivered a reply no record could match — the caller awaited a promise nothing could settle — and a transport that threw synchronously escaped `call` as a synchronous exception instead of a rejection. The record is now installed before transmission; a throwing `send` removes it and rejects exactly once, so a failed request leaves nothing pending.
- Attach could permanently desynchronize clients already attached: the attach refresh ran with publication off, so a silent append it consumed advanced the canonical Document and the read position while established mirrors received nothing — and no later refresh would resend the entry. The attach refresh now publishes its discovery to the attached clients before the new connection registers and receives the same state as its initial sync.
- A live form parented onto a sealed entry of another branch was treated as the selected continuation ("attached through a sealed entry" accepted any sealed ancestor, not one on pi's selected path). After pi branched elsewhere, the Document kept rendering the abandoned branch's live work. A live continuation must now extend pi's selected leaf.
- A leaf move with no append (a branch switch) left the previous branch's message/token/cost rollup on the newly selected branch: aggregate stats were re-derived only when an entry was installed. They now move with the selection as well, and `navigate`/`recoverTurn` go through the refresh boundary so the leaf, stats, and recovery kind all describe the new branch.
- A refresh with an empty suffix copied the whole entry map, invalidated the cached selected ancestry, and the Manager sampled context usage (a full pi session projection) after every event — history-sized work at token cadence. An empty refresh now stays O(live forms) and reuses cached ancestry, and context usage is sampled only at settle boundaries and attach.
- A refresh that installs a suffix applied one entry-add op at a time through `applyPatch`, which shallow-copies the entry map per op — quadratic on the bootstrap-sized install every session open performs (≈2.4 s for 4,000 entries). Installing a suffix now copies the map once and inserts plainly.
- A reopened session lost its title: Manager bootstrap went through the entry projection, which installed persisted `session_info` entries but never derived `status.name`. A suffix carrying a `session_info` entry now re-derives the name, so a reopen and a silent rename publish it.
- A nested tool call (made through `ctx.executeTool`) was addressed under an invented `pending:<toolCallId>` identity: the fabricated entry never sealed and never settled away, so completed nested calls left permanent unsealed entries in the Document. Nested tool events own no entry; more generally, a content event without pi's reserved `entryId` is dropped instead of being addressed under an invented identity.
- `resolveLabels` ordered label entries by timestamp then id — a set and its clear in the same millisecond could be reversed (ids are random), resurrecting a cleared bookmark. File position (`ord`) is now the order authority, matching pi's `SessionManager`.
- An authoritative same-id entry replacement could be concealed by the ViewModel memoization: `viewModelCacheKey` reads paths and content lengths, which a replacement that changes only e.g. a tool name or a label value does not touch. `DocumentMirror` now counts entry-root replacements, the pipeline bumps `pullTick` on one, and the model catalogue identity joined the key (the context percentage is computed against it).

- Status derivation selected "the latest entry" by entry-map key order. An all-digit entry id (about 2% of 8-hex ids) enumerates before every string key in a JS object, so a cached paint could derive the wrong leaf, name, model, or thinking level until the authoritative refresh landed. `deriveLeafId`/`deriveModel`/`deriveThinkingLevel`/`deriveName` now select by `ord`, the file position.
- A wholesale entry-list rewrite (a fork) was installed as if it began at the held read position: entries before it were deleted and the suffix was renumbered from zero. `refreshFrom` now re-reads the whole list when the version changes, and the projection takes its next position from the snapshot instead of recomputing it.
- A settle boundary dropped live forms while a recovery continuation (ADR 16) was still running outside pi's settle events, briefly removing the continuing run's entries from the view. Settle is skipped while the Manager tracks a recovery run; the continuation's compensated end performs it.


- The daemon no longer auto-starts a session; clients land in a "No instance selected" initial state. Instances are created on demand via the `[+]` button.
- `liveSessionId` removed from `GetDaemonInfoReply`. Per-instance session ids are now in `InstanceInfo.sessionId` from the `listInstances` verb.
- `Connection` constructor no longer takes a `Manager` parameter. Connections start unattached; call `attach(manager, instanceId)` to attach.
- `DaemonVerbs` interface expanded with routing verbs (`switchInstance`, `newInstance`, `killInstance`) and `listInstances`.

- Reconnect no longer auto-pushes a `replace` — the client drives re-attachment from its stored `attachedInstanceId`.
- `Status.model` is now a `ModelRef` struct `{ provider: string; modelId: string }` instead of a bare id string. The provider was previously dropped at `deriveModel`/`reconcile`/manager boundaries, so same-id models from different providers collided. New `ModelRef` type exported; `ReconcileOptions.model` and the `currentProviderModel` picker prop (renamed `currentModelRef`) take the struct.

### Added

- Broken-tail turn recovery (ADR 16): the new `recoverTurn` session verb and `Status.recoverableTurn` field. The tail run's boundary is derived on the host (`computeRecoverableTurn`, pure, exported) and re-derived by the client viewmodel onto the dead turn (`AssistantTurn.recovery`) — the dead turn's error row is the one failure presentation and the one recovery carrier: the real error/abort line, or a synthetic line in the same error hue when pi persisted no error (silent interruption), with the buttons beside it. The labels predict the mechanism before the click. **Retry** silently re-requests from a clean boundary — no interrupted work is re-run or re-sent, nothing is added to the transcript — and is offered with **Edit** (the composer's edit mode on the run's user message, then resend); it covers terminal errors (the dead assistant is branched past with the `navigate` machinery and the run continued via `agent.continue()`, with full settle compensation on every exit path so a failed retry re-arms instead of wedging in streaming state, and the run's lifetime tracked so abort/close await it), cleanly-stopped turns, and unfinished runs (answered tools, no final assistant — a bare seamless continue). **Send "Continue."** is the one action that adds a message — a visible `"Continue."` user turn. ### Changed

- An address-bearing publication is one store write. The replace path used to publish the new session's document before the address committed, and the delta path committed the address before the document — either order let a store subscriber observe the new document under the old address or the reverse. The new `commitObservation` store action lands the address, the durable session id, the document, and its revision together (carrying the viewer-portal and peek-pin side effects the separate `setCurrentSession`/`setActiveSessionId` writes used to apply), and the navigation reactor is its only caller: the pipeline now drops its coalesced old-session ops (the barrier) and forwards the frame instead of publishing around the reactor's commit. The delta cache write-through runs only under the session id the reactor committed, so a frame the reactor ignored (superseded, abandoned, cancelled) publishes nothing and persists nothing — previously it wrote through under the previous session's id. The replace-path cache repair stays unconditional (it rewrites the target session's cache with the server's authoritative snapshot, correct for that session id regardless of what renders).
- Navigation effects are value-only: the authority rule "a step may read and write anything; an effect may only observe and return a message" is now structural in `navigation.ts`, closing the class of races where an unordered effect write escaped the epoch machinery. The `/@latest` resolution returns as a completion carrying the epoch of the intent that started it and is checked before staging — a lookup landing after a newer navigation committed can no longer re-enter as a fresh intent and override the successor (nor can a stale "nothing to open" answer clear a committed view). An opening transition is now two-phase — the intent stages optimistically and admits a value-only prepare effect that reads the target's cached prefix; the `prepared` step does the seeding (candidate for navigate, live mirror and store for boot) and admits the open RPC — because seeding must precede the RPC: the server pushes the initial-sync frame before the reply, and the candidate or mirror must already hold the cached prefix when that frame applies. A superseded transition's prepare still sends its RPC (the reply must settle; the server serialized the transitions) but seeds nothing, so a reverse-order cache read can no longer overwrite the successor's candidate (previously the successor's delta then failed to promote and left the cache base unbound), and a superseded boot can no longer paint the abandoned session's cache into the committed view. The candidate document is the reactor's transition state (`sessionCandidate.ts` is now pure functions — `beginSessionCandidate`/`discardSessionCandidate`/`sessionCandidatePending` and `entryCache.prepareSwitch`'s seeding side effect are gone), `created` no longer re-asserts over a newer intent or an abandoned address, and every effect settles its caller on every path — an unexpected dependency throw becomes a failed transition, not a permanently pending RPC. The `abandoned` marker clears when its address commits again, so a reconnect replace for the rendered Session is no longer swallowed by a stale marker.
- Same-id content changes are now a declared projection input instead of a pull-tick side channel. `DocumentMirror.rewrites` is renamed `revision` and is also advanced by `applyReplace` — a wholesale replace is a revision of everything the mirror holds. The connection pipeline publishes the mirror's revision into a new store field, `docRevision`, together with the document it describes (at flush time, never before), and `viewModelCacheKey` takes it as an input alongside `pullTick`, `modelsKey`, and the peek override. The pipeline no longer bumps `pullTick` when a live patch replaces an entry root: the tick keeps its one meaning — lazy-pull ingests and initial-sync barriers re-registering visible lazy fields — and re-projection on authoritative same-id replacements is gated on the published revision, which the key can see.
- The history pane's `+N` fold is now thorough: it folds any off-path user turn with no user-message descendants — previously only turns whose assistant reply aborted folded, so a completed turn that was edited away (or abandoned for a later sibling from the same branch point) stayed a permanent row and lane stub. The fold predicate is structural (`HistoryNode.deadEnd` — no user message anywhere in the subtree), abort-agnostic; `abortedDraft`/`discardedDrafts`/`collapseDrafts` are renamed `deadEnd`/`supersededTurns`/`collapseSuperseded` accordingly, and the collapse exclusion is now a `keepVisible` set — the active path ∪ the rendered (peeked) path, so a dead end pinned by a peek keeps its row and click target instead of hiding behind the badge. A trailing dead end with no following sibling still stays visible (nothing superseded it).
- The conversation column now always carries tail slack: the minimum manufactured scroll range that keeps the live path's last user turn pinnable at the viewport top — the sent-message reading position, available at any time rather than only while a turn is frozen. An idle session's landing anchor now pins the last user turn exactly (previously it clamped to the bottom whenever the tail was shorter than the viewport), and a plain scroll down can park it at the top with the reply below. The slack is written as a `--tail-slack` custom property that the composer-footprint padding adds — the composer's own growth stays live in the cascade, where the old frozen-turn inline `padding-bottom` override froze the footprint for the turn's duration — and is recomputed on every content-height change (streamed-in growth below the pin trims it; shrinkage above the pin grows it back), at the send and history anchor scrolls, at go-live, and on window resize, while being skipped while peeking a committed branch. Every live-end computation (at-bottom detection, follow targets, the jump button, go-live) subtracts it, so nothing ever targets the padded end; while any slack remains the document's maximum scroll is exactly the pin position, so scrolling past it into blank is structurally impossible.
- Conversation scrolling/anchoring model reworked around the reader. A sent message (compose, steer, edit-fork, or a new session's first prompt) now top-anchors its turn container — header metadata included — and freezes auto-scroll for the turn: the reader's own message stays the reading position while the reply streams in below, instead of the viewport chasing the live tail. Because the sent message is the live tail, top-pinning it needs scroll range below it that does not exist yet — provided by the tail slack (next entry); without it the browser's max scroll clamps the anchor back to the bottom. The freeze lifts only by reaching the live end after content has grown below the parked viewport, the jump button, or a session switch (bottom-ness before anything streamed below is circumstance, not intent, and does not lift it); a scroll clamp (not enough content above the anchor) is benign because the anchored turn is then necessarily within the first viewport. Steers from other clients do not anchor — only local sends do (`sendAnchorPending` store slot armed by the commit paths with the path's last-user baseline captured at arm time — a store-side walk, immune to render timing, so the edit-fork's fork-point navigate cannot consume the flag meant for the forked message — and consumed by the viewport when the live path's last user message differs from that baseline). The anchor scroll is animated (instant under prefers-reduced-motion). The jump button's new-content dot click now top-anchors the latest reply turn (latest assistant turn, tool-only included; last-turn fallback) instead of jumping to the raw live end, and the G key targets the same turn (`latestReplyTurnKey`, new shared viewmodel export) so every "go to the end" gesture lands in one place; while a turn is frozen the button is the "follow live" gesture for the rest of the stream. History-pane anchors now use `scrollIntoView` with the turn surfaces' scroll-margin (TopBar clearance + composer clearance), fixing the old hand-rolled `- 12` offset that hid the anchored turn's header behind the fixed TopBar; the scroll-margin rule covers every `[data-turn-key]` turn surface, not just user/assistant messages.
- Cache-first boot: the store's document is always the last-known state of the watched session and renders whatever the connection says — a cold open of a previously synced session URL paints the cached content immediately (local restore in `sessionBoot.ts`, run at mount in parallel with the first connect, quiescing the cached mid-flight status behind a race guard that never lets stale cache overwrite wire data), instead of showing the Launcher's connecting panel until the daemon answers. The connection gates capabilities (mutation, RPC), never rendering; with no local truth the address stays unclaimed and the down states show as before. Scope is session-content recovery on a direct open: listing, the launcher, `/@latest` resolution, and switching sessions still require the wire.

- Sidebar interaction model: the dual open/closed panel is now tri-mode — hidden, docked rail, and fullscreen. The rail's resize handle is a mode switch with live snap previews at both bounds (preview == release predicate, so the on-screen state never lies): dragging below the min width snaps the sidebar fully shut mid-drag — the width clamps at the min until the threshold, then pane and gutter disappear at once, and dragging back wider within the same gesture snaps it back open — while dragging past the max width snaps the fullscreen overlay in mid-drag (dragging back under the max snaps it out; the drag keeps its pointer capture under the overlay). The release decides: below the min hides the sidebar, above the max fullscreens it (pure overlay above the top bar, close button docked at the hamburger's corner position so the same screen corner toggles it, plus Esc; `--sidebar-w` stays 0 so the conversation keeps full width), and both overshoot releases restore the pre-drag width first, so backing out of either state is an undo. Mobile drops the half-width drawer for the same full-screen overlay and has only hidden/fullscreen. The top-bar hamburger shows only in mobile mode or desktop-with-sidebar-hidden; on desktop it toggles the rail and hover-peeks a temporary drawer (full-height overlay above the top bar, same content, hides when the pointer leaves, with a short grace timer bridging the hamburger→drawer gap; its own hamburger button at the top-bar hamburger's position pins the rail open — one corner toggle: hamburger opens, peek's hamburger pins, fullscreen's ✕ closes), and an always-invisible 12px drag strip at the far left edge (full viewport height, col-resize cursor only) reveals a hidden rail pointer-absolute — the implied width is the pointer's x position and the rail appears only once that exceeds the min (before then the drag previews closed; a release below the min keeps it hidden with the pre-drag stored width restored). Rail visibility persists in localStorage independent of the rail width; `ResizeHandle` gained opt-in `onOvershootChange` (live snap preview) + `onOvershoot` (release decision), HistoryPane behavior unchanged.

- Beautified bash step summaries (collapsed fold row only), in two decorations: command words get tinted chips — the first command of every separated segment (env assignments like `FOO=1` don't count and keep the expectation alive) plus its subcommand for known multi-word tools (`npm run`, `git commit`, `cargo build`, …), with boring text/file utilities (`ls`, `head`, `tail`, `rg`, `sed`, `cat`, …) left plain — while abbreviated tokens render dimed italic: a leading `cd <dir> &&` folds by its relation to the cwd (under it → `cd dir`; equal to it → no-op `cd;`; outside it → `cd …last/two &&`), and any path-shaped word with more than two real segments folds to its last two. The rules now run over a quote-aware piece scanner (new `scanShellPieces` export) instead of regexes over the raw string: quoted spans are opaque (separators and paths inside `"…"`/`'…'` are never decorated — `rg "foo|bar"` no longer chips phantom commands), and `&&`/`;`/`|` only separate when unquoted. Ad-hoc heuristics, no shell parsing; abbreviations carry the original on hover, the raw command stays the aria label, and the expanded card's identity line still shows the command unmodified.

- Action group headers name only the changed files, and pull less: the collapsed label lists edit/write basenames together under one category plus counts (`edit: a.ts, b.ts · run 2 tools · read 3 files`) — the bash key command (and its `2>&1`-mangling `extractKeyCommand` split) is gone from the header, and every non-edit/write tool renders as a count, needing no arguments (edit vs write stays visible in the expanded step rows and card identities). The group-level `arguments` pull is restricted to edit/write steps; per-step argument wants moved into `ToolActionStepView` (mirroring `ThinkActionStepView`), so expanded rows keep their live summaries while collapsed groups fetch nothing for bash/read steps.

The daemon-side extractor skips text-less messages (tool-call-only assistant turns); `lastActivityAt` still tracks the newest entry of any kind.

- `listSessions` is scoped to the attached instance's cwd and filters out live sessions.
- `listFiles` takes an optional `cwd` parameter for per-instance path completion.
- `manager.dispose()` now awaits `session.abort()` before emitting `onExit` and tearing down the runtime (ensures "save first, then tear down").
- Web client `useConnection` fetches `listInstances` + `getDaemonInfo` on connect, and re-attaches via `switchInstance` if the stored instance id is still alive.
- `useConnection` auto-seeds at zero live instances: on connect with no live instance and a non-empty cwd allowlist, it creates one instance per allowlist cwd — each resuming that cwd's most recent prior session (fresh on first use) — and attaches to the last. The Launcher's empty state is now only reached when seeding fails or the allowlist is empty; >1 live instance still lands on the Launcher for picking.
- Web client reorganized into a layered structure under `web/src/`: `app/` (shell — `App`, `main`, `index.css`, `ToastBar`), `infra/` (`store` + `client`/`useConnection`/`useRpc`/`pullLoop`/`wants`), `render/` (`markdown`/`CodeSnippet`/`shiki`), and `features/<area>/` (`topbar`, `sidebar`, `conversation`, `composer`, `history`). `App`, `ConversationArea`, and `Composer` split into per-component files with co-located `.module.css`; `useConnection` split into `client` (singleton), `pullLoop` (wants-outbox drain), `useRpc` (verb wrappers), and `useConnection` (WS lifecycle). Pure reorganization — no behavior change.

- Composer commit is now atomic: `handleCommit` clears the draft only after the prompt/navigate RPCs resolve `ok`, so a failed or offline send leaves the text intact for retry. The previous flow cleared the textarea before the RPC could fail (permanent loss on disconnect).
- Composer blur semantics: blurring an edit draft salvages the typed text as a compose draft if modified (`text !== initialText`), or discards to idle if unmodified — a no-op edit blur yields an empty bar, a modified edit blur preserves the text. The old behavior orphaned `editingEntryId` in the store while the local textarea text was lost on collapse.
- Store fields `editingEntryId`/`editingIndex`/`editingInitialText` replaced by a single `draft: ComposerDraft`; `setEditingEntryId` replaced by `setDraft`/`setDraftText`/`beginEdit`/`blurDraft`/`clearDraft`.
- `switchSession`/`newSession` RPC wrappers now refresh `listInstances` so the attached instance's current `sessionId` (used to key draft persistence) stays in sync after a session switch.
- Compact wire form for streaming appends: the WS transport (`Connection` on the host, `BridgeClient` on the client) now holds a stateful `CompactCodec`. Consecutive single-op `append` patches to the same path are emitted as bare JSON strings (no frame envelope); the decoder restores the append op before the mirror sees it. Upper layers (diff engine, `DocumentMirror`, `onPush`) are untouched. Cuts streaming-append envelope overhead ~12× (a 33K-token thinking stream: ~3.66 MB → ~300 KB on the wire). See `docs/06-component-model.md` §Push.
- `computeObjectDiff` now recurses into arrays element-wise instead of replacing the whole array atomically. A streamed array argument whose element string field grows by a suffix (e.g. an edit tool's `edits[].newText`) now emits `append` on the element sub-path — O(n) wire cost — instead of re-sending the whole array per token (was O(n²); the `edits` stream alone was ~8.67 MB for a ~10 KB final value).
- Consecutive `model_change`/`thinking_level_change` entries (pi writes them back-to-back on a model switch — `setModel` appends the model change, then the thinking re-clamp appends a level change) now collapse into a single `model_switch` system turn reporting the run's final state (last model, last thinking level; the level is omitted when the run didn't change it). The web UI renders it as one normal-case markdown line — `Model: **DeepSeek V4 Flash** (via DeepSeek, thinking high)`, keeping the divider rules on both sides — using the daemon's curated model display name and a new `ModelInfo.providerName` field (from pi's `Provider` registry, e.g. "DeepSeek"), instead of one all-caps divider per entry. `SystemTurn.detail` removed; new `SystemTurn.switchTo` field. `SystemTurnType` is now `"compaction" | "branch_summary" | "model_switch"`.

- The Project home (`/<projectId>`) is compose-only: the active-sessions and recent-history lists are gone from it — the home shows just the centered compose card, and Projects + active sessions are listed only at the global launcher (`/`). Project sessions are browsed from the sidebar. The client-side plumbing for the home's history page is removed with it (the store's `sessions`/`sessionsHasMore`/`sessionsNextCursor` slice, `appendSessions`/`replaceSessions`, `loadProjectHome`, `loadMoreSessions`, and the `listSessions` fetch on every Project-home open / failed-open fallback).

- App decomposed from a 613-line controller into a ~300-line shell plus three behavior hooks, no behavior change: `useViewModel` (infra) owns the store→ViewModel projection and cache (the 11-field hand-maintained cache key moved into viewmodel as `viewModelCacheKey`, beside `leafPathKey`/`leafStreamingKey`, so a new projected `Status` field can't silently miss the key; the hook also selects the whole document instead of reassembling it from eight primitive selectors); `useComposerCommit` (composer) owns the draft→wire commit/fork flow (compose prompt, edit-fork-via-navigate, optimistic clear + failure restore); `useKeyboardRing` (infra) constructs the full `AppKeyHandlers` set, with the j/k step math extracted as pure `nextFocusedTurnKey` (turn-key identity contract) and the notification icon as pure `liveActivityPhase`. All three viewmodel additions are exported and covered by new unit tests (`viewmodel-keys.test.ts`).

- Compose surfaces deduplicated: `useComposeCapabilities` owns the attachment + path-completion wiring shared by `ComposeDock` and `HomeCompose` (both read the same store draft, so it owns the value/onChange pair too) and returns a typed `Pick` of `ComposeCardProps` that both spread, keeping the card's explicit presentational interface. ### Fixed

- A silent recovery continuation (`recoverTurn` → `agent.continue()`, outside pi's `_runAgentPrompt` wrapper) was instantly killed by a stale stop flag after any user Stop of a normal run (frame-log capture: every retry died within ~20ms with "This operation was aborted", re-arming the affordance in a loop). pi's per-run abort flag was reset only by the next `prompt()`; it is now consumed when the run settles (core fix in `AgentSession._emitAgentSettled`), so wrapper-less continuations start clean. Regression-tested in `test/suite/recover-turn.test.ts`.
- A silent recovery continuation (`recoverTurn` → `agent.continue()`, outside pi's `_runAgentPrompt` wrapper) was invisible to pi's own busy state, so a Stop or a session close during the recovered run returned before the run flushed — the terminated tail could be lost on teardown. The Manager now tracks the continuation's lifetime; `abort` and `dispose` await it, so the aborted tail is persisted and re-derived (`recoverableTurn` re-arms) before either returns. Regression-tested over the full event pipeline with a gated faux response (`test/suite/recover-turn.test.ts`).
- Turn-completion notifications never fired on Firefox Android while the tab was backgrounded: the streaming→idle transition was detected in a render effect fed by the pipeline's coalesced store write (rAF visible / 1s `setTimeout` hidden), and backgrounded tabs suspend both — the completion patch sat in `pendingOps` until the resume flush, where the stale-`document.hidden` grace guard then correctly suppressed the notification for the foregrounding user. A patch touching `/status` now flushes synchronously in the pipeline (urgency rule alongside the existing replace barrier), the transition is detected in `useStatusNotifications`' store-level subscription (at frame-arrival time, when `document.hidden` is trustworthy), and the 1s grace `setTimeout` — which could never elapse while hidden — is replaced by a `document.hidden` re-check after the async service-worker registration hop. The flush policy is regression-tested in `web/src/infra/net/connectionPipeline.test.ts`.
- The history pane's lane graph grew one lane per re-edit cycle after a history revisit-edit (edit a message, continue, edit the next, continue …, then go back and edit an earlier node): off-path branch points picked the *oldest* child as primary and secondary siblings were assigned lanes oldest-nearest, so the chronological continuation — a chain of secondary children, each forking strictly right of the previous link's lane — cascaded one lane further right per cycle with no lane ever reusable. Off-path branch points now pick the *newest* child (where the conversation continued) as primary, and secondary lanes are assigned in reverse chronological order (newest nearest the parent): the spine inherits one lane straight down and every superseded original is a one-dot stub reusing a single stub lane. Lane count is now constant (3: active, spine, stubs) regardless of the number of edit cycles; nothing is hidden.
- A send armed while the previous message was still uncommitted anchored the PREVIOUS message instead of the sent one. The send-anchor baseline was the tail user message's entry id — but while a turn is in flight that message is a `pending:user:` provisional, and the seal re-keys it to its real persisted id, so the id-only comparison consumed the flag on the re-key (a steer sent mid-run pinned the message before it, and the steer itself never anchored). The baseline now carries the message's content fingerprint (`SendAnchorBaseline` — text blocks inline, other blocks by type marker; pull-stable and never rewritten by the re-key), and the new pure `consumeSendAnchor` predicate skips the re-keyed baseline. Accepted cost: identical consecutive messages (same text and block shape) miss the anchor and fall back to plain bottom-follow. Regression-tested over the real event pipeline (`test/suite/send-anchor.test.ts` — sequential turns, the mid-turn steer, and the hand-built re-key).

- A system-role message (pi's prompt-section diff) rendered as a duplicate empty user turn beside the real one. The turn dispatch treated every non-assistant message as a user turn; it now routes a system message to a `system_prompt` turn, rendered as a `System prompt update` card naming the changed sections and showing the section text on expansion.
- Unclassifiable entries were dropped silently, and extension-owned custom entries were mislabeled `Unrecognized`. The projection now separates three cases: an upstream type it cannot classify becomes an `unknown` entry (rendered as the unrecognized fallback, raw payload preserved), an extension-owned custom entry becomes an extension turn named by its custom type, and a named non-conversation type (context edit, usage record) becomes a hidden `internal` entry. The entry-kind and turn-kind switches are exhaustive, so a new kind is a compile error.
- Assistant image blocks and unrecognized content blocks were dropped by the block builder. Both now render a visible placeholder; an unrecognized wire block no longer becomes `[object Object]`.
- A system message's prompt-section text shipped eagerly (~53 KB for a full prompt) on every initial sync and into the cache. The section names are now eager (for the collapsed summary) and the text is lazy, pulled when the card expands.

- Mid-turn git stamps collapsed the live conversation to a lone git card and then remounted every turn at the seal (blank page plus a CPU spike — a ~500 ms main-thread task on long sessions). A `tool_end` stamp is appended with `parentId` = the real persisted assistant entry id, which the live Document only knows as the `pending:message` provisional until the turn-end reconcile; `applyEvent`'s `entry_appended` moved `status.leafId` onto the stamp, the leaf-path walk broke at the unknown parent, and the ViewModel projected a single `GitChangeTurn` until the seal restored all turns with zero identity reuse — every turn remounted and every Markdown block re-parsed. `entry_appended` events whose parent chain does not resolve in the Document now defer to the seal: reconcile discovers them from the session file under its normal pairing conditions. Known-parent appends (prompt stamps, bash entries and their `user_bash_end` stamps) still apply live; the mid-run git card consequently appears when the run settles instead of during streaming.
- ADR 11 activation leak: a WebSocket that closed while its `openSession`/`newSession` RPC was still creating the pi runtime still got attached once creation finished, and nothing could ever release the dead Connection — the activation's GC never armed and the runtime leaked for the daemon's lifetime. `Connection` now tracks disposal and the daemon skips the attach (arming normal idle GC for the orphaned activation instead).
- HTTP static serving used a string-prefix containment check (`filePath.startsWith(root)`); because `join()` resolves literal `..` components, a raw request like `GET /../web-x/secret.txt` (curl `--path-as-is`) escaped into sibling directories of `webRoot` sharing its name prefix. The check is now the same path-boundary `isContained` rule the session scanner uses.
- Markdown typography no longer escapes shrunken host contexts: Streamdown hardcodes rem-absolute `text-*` utilities (inline code, table cells, `sup`/`sub`, `h1`–`h6`) calibrated for the 16px document baseline, so in 12px contexts (thinking prose, tool-card `.md` prose) inline code rendered at 14px inside 12px paragraphs and an `h1` at 30px. One global block of em-equivalent overrides (`web/src/app/index.css`) now scales them with the host — the 16px document is pixel-identical, mobile (14px body) follows the shrunken baseline — replacing the per-surface `.markdownContent code` / `.thinkBody code` ratios (ADR 07 styling invariants #2/#4).

- Tool failures now display: the skeleton's error strip renders the tool-result error text for every card kind (previously failed `edit` calls rendered the attempted diff with no indication of failure — the body never read the result).

- Launcher instance rows now head-truncate the cwd (CSS `direction: rtl` + `<bdi>` isolation) so overflow clips from the left and keeps the discriminative path tail visible; the full path remains in the row's title tooltip.

- Clicking the live session's stub row in the sidebar (a bare session id pushed by the `newSession` push, shown until the session file lands on disk) no longer creates a junk `<session-id>` file in the daemon cwd. `Manager.switchSession` treated the id as a file path, so `SessionManager.open` resolved `cwd/<uuid>` and wrote the conversation there; it now no-ops when the target is the already-attached live session.

- Model picker disambiguation: when two providers offered the same model id (e.g. "claude-sonnet-4-5" under both Anthropic and an OpenRouter-compatible provider), Ctrl+P cycling started from the wrong provider's slot, the composer ghost button showed whichever provider sorted first, and the picker highlighted *both* same-id rows. Root cause was `Status.model` storing only the id; it now carries the `{ provider, modelId }` pair. New pure viewmodel helpers `findNextModel` (cycle) and `isModelSelected` (picker highlight) key on the full pair.
- History pane: SVG verticals/fork curves were offset 8px from the DOM dots. Breathing room moved from `.content` (whose padding box is the origin for absolutely-positioned children) to `.scroll`, so SVG and rows share an origin and dots sit on line endpoints.
- History pane: lane width narrowed (40→24 px) so multi-branch graphs no longer dominate the pane or truncate the label column on mobile.
- History pane: the "current" dot now marks the deepest on-path user message (stable across assistant turns) instead of only matching when the leaf was itself a user message.
- History pane: the drafts toggle badge was click-through — `.label`'s `pointer-events: none` was inherited by the badge, so clicks fell through to the row (navigating instead of toggling). The badge now re-enables pointer events.

- Edit-mode blur orphaned the editing pointer: the dimmed branch stayed in the conversation while the textarea text (local React state) was lost on collapse, leaving the view dimmed with no backing text. The draft is now the single source of truth for both dimming and the textarea.
- Sending while disconnected permanently lost the input: `handleSend` cleared `input` before the (no-op, disconnected) RPC fired. Commit is now atomic — the draft clears only on RPC success; a connection pre-flight toasts and keeps the draft.
- Closing the tab with unsent text neither warned nor remembered: a `beforeunload` listener now warns, and compose drafts persist to per-session `localStorage` and restore on reload.
- Composer input not resetting after a successful send: `Manager.prompt` awaits the *whole turn*, so clearing the draft only after the RPC resolved left the sent text in the textarea through the entire stream. The commit now clears the draft optimistically (before the RPC await) and restores it on failure, so the textarea empties immediately and a failed/offline send still keeps the text.
- Edit mode not exiting on blur when the bar was already expanded: `beginEdit` set `composerExpanded: true` but the focus-on-expand effect (deps `[expanded]`) didn't re-run when expanded was already true, so the textarea never gained focus — a later click-away couldn't blur it and `blurDraft` never ran. A second effect now focuses the textarea when an edit begins.
- Removed the `commitInFlightRef` Enter-dedupe: it blocked steering during a turn (the "RPC latency" it guarded is the whole turn). The optimistic clear makes a second Enter a no-op (empty draft), so the dedupe is both unnecessary and harmful.
